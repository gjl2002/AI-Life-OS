# 专注计时

通过 [计时数据源与字段](references/notion-runtime.md) 使用 `ai-life-system-init` 的 Runtime 定位用户自己的「计时」。执行时读取实时 Schema，用用户已确认或当前运行环境可确定的时区核对时间。将带时区的开始与结束时刻交给连接器。只有当前请求已授权记录或修改这段计时时，才调用写入工具。

## 开始计时

1. 确认活动名称。先在目标源查找进行中的计时。有多条候选时请用户确认。仅有一条且为同一活动时回报现状，活动不同时确认如何处理。
2. 从当前时钟读取开始时间。使用实时 Schema 里表达进行中的状态，写入标题和开始时间。按实际字段决定是否记录时间分类、时间范围起点或关联。
3. 在目标 Data Source 直接创建页面。回读核对归属、活动、开始时刻和进行中状态。返回开始时刻和记录链接。

## 结束计时

1. 用户给链接或明确指明记录时，先核对它属于已绑定的数据源。否则查询进行中记录。仅有一个明确目标时才能更新。多条候选时请用户指出要结束哪段。已结束的记录可以直接回报其状态。
2. 从目标条目回读原开始时刻，用用户指定或实测的当前时刻作为结束时刻，核对结束晚于开始。写入完成状态与结束时间。如果还要更新日期区间，同时传入真实的原开始时刻和结束时刻。
3. 回读核对区间和状态。用实际开始和结束计算回执中的时长，公式字段由 Notion 计算。

## 补记已经结束的活动

1. 确认活动和结束时刻。优先使用用户给出的开始时间，或由已确认的结束时间与时长反推。用户以「上一段结束后」等线索承接，或未给开始时间时，实查同一当地自然日内最近已结束的记录，并以该条目的实际结束时间作为候选。找不到可用承接点时，问用户开始时间。
2. 先查活动名称和起止时刻是否完全匹配已有记录，命中时回报已记录。再核对先后顺序、合理时长及区间重叠。跨天承接、短活动却跨度很长、或和已有计时重叠时，先向用户确认。存在正在计时的记录时提示其状态，确认独立补记的边界。
3. 按活动名称、开始、结束和完成状态直接新建。保留此前记录。若时间源于用户估算，在回执中标注。提供区间、可计算的时长和页面链接。

## 写入核验

写前按实际动作调用 Runtime 的 `check-write`，核对实时的目标、字段、状态选项和有效关联。写后读取页面核对标题、状态与时间。异步结果需确认完成；连接中断或返回状态不明时，先按已有页面 ID 或创建条件查回，再决定是否重试。
