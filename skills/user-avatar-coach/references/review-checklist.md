# 用户画像质量检查

## 来源与 Runtime

1. 是否通过 `$ai-life-system-init` Runtime 解析真实“用户画像”和必要商业来源？
2. 是否实时读取了用户指定的云端页面、记录或数据库？
3. 是否避免本地 Notion Sync、固定 ID、个人路径和全库扫描？
4. Relation 是否只作为候选范围，而不是默认全文读取？

## 证据

1. 是否存在真实用户材料？
2. 关键判断能否追溯到具体来源、时间和用户身份？
3. 是否保留了能体现场景、情绪、抗拒、选择或购买意图的用户原话？
4. 是否清楚区分已确认事实、合理洞察和待验证假设？
5. 商业定位、产品说明、理论和竞品是否只作为背景，没有冒充用户证据？
6. 正式画像是否达到 Level 1 或强 Level 2 门槛？

## 分群与购买逻辑

1. 分群是否来自 JTBD、触发、替代方案、购买逻辑、信任要求或使用场景的真实差异？
2. 是否避免按年龄、城市、职业等装饰性人口标签过度分群？
3. 是否解释为什么购买、为什么不购买、何时产生紧迫感、什么建立信任？
4. 是否识别了不适合用户或使用者与购买者的差异（如材料中存在）？

## 产物与职责边界

1. 输出是阶段小结、用户画像假设还是正式用户画像，是否与证据强度一致？
2. 是否说明仍然不知道什么以及什么信号会改变判断？
3. 是否只输出对商业定位、产品、内容和销售表达的约束与交接？
4. 是否错误地继续完成了完整商业定位、产品架构、内容计划、销售页或销售 SOP？

任一关键证据门槛失败时，降级为用户画像假设，不为了结构完整填造内容。

## 云端写回

- 是否获得用户明确授权？
- 是否重新解析 `user_profile` 并实时读取 Schema？
- 是否搜索了重复或可更新画像？
- 是否对本次所有字段和选项运行 Runtime `check-write`？
- 是否保留无关正文和现有有效证据？
- 是否写后回读并核对关键内容？

阻塞项未解决时不得写回正式画像。
