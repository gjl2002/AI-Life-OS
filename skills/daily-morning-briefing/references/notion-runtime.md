# Notion 读取与写回

## 接入

调用 `ai-life-system-init` 的 `runtime.py status`。用 `resolve --concept <key>` 查找实际 Data Source，必要时按用户提供的链接或真实源名称消歧。`needs_init` 时可引导用户初始化。重名、实际结构不明或权限不足时，只报告受影响的项目。预览可继续使用用户显式提供的信息。

查询前读取实时 Schema，并按它的实际字段与选项设置筛选。下面的中文状态是语义示例。同一语义有多个候选字段且会改变结果时，请用户确认。使用者的运行索引和连接只属于其自身工作区。

## 读取清单

| 语义概念 | 读取范围与用途 |
| --- | --- |
| `daily_record` | 取当天与昨天，读取昨日结果与今日已确认安排。需要保存时核验当天唯一记录。 |
| `task` | 查今天到期，以及尚未完成且影响今天或本周交付的任务。读取能核实的状态、日期及项目或目标关联。 |
| `weekly_review` | 查当前周计划。执行评分对应实际周区间，本周未评时可单列最近有记录的周。 |
| `twelve_week_review` | 查正在进行的周期，读取业务日期、周期目标和项目关联、进度及平均执行率。 |
| `goal`、`project` | 沿实际关系读取相关周期目标和正在推进的项目。查明任务到项目或目标的路径，关联缺失时标明。 |
| `information` | 独立查询主学习状态为「学习」或实际等义选项的记录。内容加工或待收集记录单独理解。 |
| `book` | 独立查询主状态为「正在阅读」「待整理笔记」或等义值的记录。兼看阅读进度，状态矛盾时列出待核验字段。 |
| `course` | 独立查询主状态为「学习中」「笔记待处理」或等义值的记录。字段具备时按实际已学和总节数呈现。 |
| `emotion_log` | 仅在用户已授权本次晨报参考情绪记录时读取近 14 天，建议只看与执行体验有关的自述和记录。 |
| `timer`、`habit` | 仅在会改变容量或周行动判断时按本周和当前周期收窄读取。 |
| `daily_report` | 仅在需要保存时解析共享「日报」。按实际目标链接、实时身份和标题/标签/关系字段确定唯一数据源。 |

学习进度按三库独立查询。「每日记录」缺少学习关联与学习库真实结果分别呈现。部分来源不可读时，以表内名称标记缺口。读取内容限于本次时间和任务范围。

## 写回步骤

1. 核对用户授予的当次保存权限，或自动化中已有的晨报写入授权。核验共享「日报」的实际标题字段、「标签」单选的精确选项「晨报」和指向 `daily_record` 的真实 relation。用户已有两个叫「日报」的源时请其确认准确目标。
2. 查询本业务日期唯一的「每日记录」，并确认其属于 relation 指向的数据源。无法核验唯一归属时，在预览中说明具体缺口。
3. 在同一日报源按完整标题 `YYYY-MM-DD 晨报` 和 `标签 = 晨报` 查重。唯一命中时只改晨报生成内容和用户授权的字段。无匹配、无同标题异标签历史冲突时创建。存在多页或同标题异标签时说明冲突。
4. Runtime 的 `check-write` 使用当前动作与实际字段。创建时必检标题、标签和 relation，同时传精确选项 `标签=晨报`。更新时校验本次修改的字段，并确认已存在的标签和关联。预检通过后核对云端实时 Schema 与归属，再提交。
5. 回读新旧页面，核对标题、父 Data Source、标签、当天关联、三类学习进度及生成正文。如有引用，核对链接。回读截断时优先获取实际段落，状态不明时先按 ID 或查重条件确认结果，再决定是否重试。

晨报写回目标是用户既有的「日报」页。数据库、属性、标签选项、定时器和其他行动记录由用户通过各自流程管理。
