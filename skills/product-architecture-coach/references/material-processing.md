# Material Processing

Use this reference when actively searching, collecting, and turning notes, experience, prompts, transcripts, tools, and examples into product materials.

## Source Search Contract

Do not treat "raw material" as only what the user pasted. When the product architecture depends on real substance, search the user's current cloud records and explicitly supplied files before finalizing the blueprint.

Search in this order when available:

1. User-supplied files, pages, notes, transcripts, prompts, and product drafts.
2. The target `product` record and its relevant linked pages.
3. `commercial_positioning` as the public positioning and boundary constraint.
4. `user_profile`, `user_feedback`, and `client_communication` for first-party demand, objection, and delivery evidence.
5. The user's existing product assets through `ai_agent` and `ai_toolbox` when relevant.
6. `note`, `information`, `book`, `course`, and `question` for methods, examples, cases, and teachable raw material.
7. `benchmark_product` when comparison or structure teardown is needed.
8. Current public web sources only when the user requests external research or time-sensitive market comparison.

Search by product name, target-user problem, desired result, method names, module names, and key verbs. First inspect metadata and relation context, then fetch only records likely to influence the blueprint. Do not scan every record merely because it is related.

If a runtime concept resolves but no relevant object-level evidence is found, mark it as `未找到相关材料`. If a concept cannot be resolved or read, mark it as `未读取/不可用`; do not treat the existence of a database or relation as evidence.

## Source Classes

Label every useful material as one of:

- `用户本人实践`: user's own systems, screenshots, workflows, agents, records, reflections.
- `用户/私域证据`: user questions, objections, consultation records, comments, testimonials, forms.
- `产品资产`: product pages, outlines, templates, prompts, rubrics, manuals, previous offers.
- `课程学习材料`: notes or transcripts from courses the user paid for or studied.
- `对标材料`: benchmark products, sales pages, accounts, public cases.
- `知识模型`: frameworks, books, articles, theories, concepts.

Use user-owned materials as higher-trust delivery material. Use paid-course and benchmark materials as internal learning inputs, not as copy-ready content.

## Processing Methods

Use two primary operating methods:

```text
拆迁法 = 拆解 + 迁移
收租法 = 收集 + 组合
```

### 拆解

Break a strong product, page, lesson, workflow, or case into components:

- user problem
- promise
- steps
- tools
- proof
- task
- feedback
- CTA

For paid-course materials, extract structure and mechanism only:

- demand logic
- stage design
- assignment format
- feedback rhythm
- pricing/offer logic
- demonstration style
- quality gate

Do not copy proprietary wording, lesson flow, examples, screenshots, or claims into the user's outward-facing product.

### 迁移

Move a pattern into the user's product context. Preserve the underlying mechanism, not surface wording.

Example: migrate "mission-goal-rule-feedback" from game/community design into a training camp assignment system.

Migration must name:

- original mechanism
- user's product context
- target user's obstacle
- adapted product element
- what must not be copied

### 收集

Gather materials around one useful node:

- a strong account
- a useful product page
- a real user question
- a repeated private-domain objection
- a working internal workflow
- a course note with many linked concepts
- a product page with clear deliverables
- a user's own system screenshot or template

### 组合

Combine materials into:

- product path
- module structure
- SOP
- checklist
- template
- workbook
- case library
- feedback rubric

Combination should produce a product artifact, not a pile of references.

### 提炼

Extract a decision rule, framework, or self-check from messy experience.

### 演示

Turn an abstract method into a visible example:

- before/after
- filled template
- screenshot walkthrough
- sample assignment
- review example

## Material Gate

For every proposed module, ask:

- Do we already have enough raw material to teach this?
- Is there a visible example?
- Can the student complete a task from it?
- Can we judge whether the task is good enough?
- What material must be created before selling or delivering it?

If a module lacks raw material, keep it in `later` or mark it as `待补材料`.

## Product Raw Material Map

For formal product architecture work, output a table like:

| 材料来源 | 类型 | 可拆解内容 | 可迁移机制 | 可加工产物 | 使用边界 |
| --- | --- | --- | --- | --- | --- |

`使用边界` should state:

- can be used directly as user's own asset
- can be adapted after anonymization
- can be used only as internal inspiration
- needs permission or replacement
- missing proof, needs validation
