# 初始化失败处理

## Hub 问题

- 没有 Hub URL：有限搜索课程约定名称，多个候选时让用户确认。
- Hub 无法读取：提示重新分享给当前 Notion 连接；不要索要 token。
- Hub 没有数据库引用：请求正确 Hub 或由用户手动提供数据库链接，不切换为全局扫描。
- Tabs、同步块等结构未被 API 暴露：说明限制，建议把数据库链接放到 Hub 普通布局中，或逐个手动补充。

## 普通页面问题

- 系统入口未精确匹配：不扩大到全局搜索；让用户确认成长、商业、生活系统入口，或提供页面 URL。
- 系统入口可读：只展开其直接子页面，深度到 2 后停止。
- 核心页面没有直接暴露：允许用户提供页面 URL 并记录 `user_override`，不扫描整个工作区。
- 同名普通页面：语义状态标为 `multiple`，由业务上下文或用户确认消歧。
- 普通页面不可读：标记 `needs_attention`，只阻止依赖该页面的动作。
- 页面只有正文变化：业务 Skill 实时读取最新正文，不要求重新绑定。
- 页面被删除并重新创建：原 page ID 失效，执行 `rebind`。

## 候选与语义问题

- 重复候选：按规范化 ID 合并，保留来源证据。
- 标题只有部分相似：不自动建立语义映射，仍可通过事实索引查找。
- 同名或同语义多个真实目标：标为 `multiple`，由后续业务上下文消歧。
- 用户明确覆盖：记录 `user_override` 和覆盖原因，但仍校验 Schema。
- 语义概念未找到：直接省略，不作为缺失或警告。

## Schema 问题

- 单数据库不可访问：标记 `retrieve_failed`，继续其他对象。
- 多 Data Source：逐个读取；失败的子 Data Source 单独标记。
- title 字段不存在：仍允许读取，但 `access.create_page_ready: false`。
- relation 目标不可解析：关系字段只读，不虚构目标。
- 空数据库：不是失败；Schema 可读且查询成功即可。

## 连接与限流

连接失败、超时或限流时可以做少量只读重试；持续失败后停止并报告。不要在权限错误上无限重试，也不要改用旧索引冒充实时状态。

## 配置问题

- 发现文件格式错误：生成器退出，不触碰旧配置。
- 语义别名文件错误：视为发布包问题，停止并保留旧配置。
- 输出替换失败：恢复备份；报告恢复是否成功。
- 健康检查发现指纹变化：转为重新绑定，不允许写入型 Skill 继续使用旧 Schema。

## 冒烟测试

- 查询成功但零记录：`passed` 且 `empty: true`。
- 数据源不可查询：`failed`，区分权限、ID 失效和工具错误。
- 未提供查询工具：`not_run`，初始化可以完成，但健康状态给出警告。
