# Opening Lesson Design / 开营课设计

Use this reference for `开营课`、`启动课`、`第 1 课`、`D0/D1`、`导入课`, or any lesson that asks a learner to enter a new course path.

## Definition

An opening lesson is the course's first act of transformation. It does not primarily introduce a product or explain rules. It makes the learner understand:

1. what problem they are actually entering the course to solve;
2. why their familiar way of solving it keeps failing;
3. what first principle and causal mechanism make the new path different;
4. how the whole course turns that principle into a result, with honest boundaries;
5. what personal asset they will create today and carry into the next lesson.

## Opening-Lesson Contract

Before writing, state these seven fields:

| Field | What must be clear |
| --- | --- |
| Learner starting scene | A concrete moment, recurring frustration, or desired change in the learner's own language |
| Old path | The habitual but insufficient way they currently try to solve it |
| Root mechanism | Why that path breaks structurally; do not attribute it to laziness or lack of willpower by default |
| Course first principle | One stable judgment the remaining lessons will test, use, or operationalize |
| Transformation path | Current state → stages → observable course result; each stage has a role |
| Learning contract | Cadence, minimum action, how interruption is repaired, and what feedback is for |
| First learner asset | A small but real record/template/system object the next lesson will directly consume |

## Required Course Arc

Use this sequence unless there is a documented reason to change it:

```text
scene or aspiration
→ reframe the apparent problem
→ show the causal mechanism behind the old path
→ state the new first principle
→ make it believable with a real case, evidence, or bounded demonstration
→ show the course transformation path
→ establish the learning contract
→ create the first learner asset
→ close with the next lesson's exact use of that asset
```

The course directory belongs after the new principle and before the first task. A student should see it as a necessary route, not a list of topics.

## First Principle Test

A usable opening-lesson principle is:

- causal: it explains why a result happens or fails;
- operational: later lessons can turn it into actions and assets;
- bounded: it does not claim to solve all of life or all business problems;
- memorable: it can be stated in one sentence without a slogan pile;
- evidenced: the lesson can show a real case, user material, mechanism, or clearly marked hypothesis.

Weak: `这门课会让你更好。`

Stronger shape: `When [the learner keeps a certain kind of real input] and [the system turns it into a repeatable feedback loop], [a previously generic / broken decision] can become more specific and actionable.`

## PPT Rhythm Board When A Deck Is Requested

Only when a deck or screen-led opening lesson is requested, specify for each designed PPT page: `page role | screen sentence / visual | spoken purpose | evidence or demo | transition`.

Default sequence:

1. entry question or recognition scene
2. old-path contrast
3. root mechanism map
4. first-principle statement
5. evidence / before-after / bounded case
6. transformation path (course map)
7. learning contract and working boundary
8. first asset instruction and filled sample
9. closing commitment and next-lesson bridge

Plan live product/software demonstrations as separate `live demo` nodes; never confuse them with designed PPT pages.

## First Learner Asset

The first asset must not be a generic intake questionnaire. It should be a minimum usable input to the system the course teaches, such as:

- a decision baseline;
- a problem definition card;
- a current-state map;
- a goal / constraint statement;
- a first system record;
- an activation template populated with real material.

It must have a submission format, a minimum quality rule, and an explicit use in the next lesson.

## Anti-Patterns

- only explaining who the instructor is or what the product contains;
- motivational language without a changed explanatory model;
- showing all tools before the learner understands the problem;
- promising a total life transformation while hiding constraints and required practice;
- assigning a broad self-survey that no later lesson actually uses;
- using a course map as a substitute for explaining causal progression.

## Opening-Lesson Quality Gate

Before release, ask a representative learner:

1. Can they name the real problem, not just the course topic?
2. Can they explain why their old approach failed without blaming themselves?
3. Can they repeat the course first principle in their own words?
4. Can they see why the stages are in this order?
5. Did they create something today that makes the next lesson easier?

If any answer is no, repair the arc before polishing language or slides.
