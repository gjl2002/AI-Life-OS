## 用户自己的 Notion 接入

本 Skill 使用 `$ai-life-system-init` 定位用户自己的 Notion 结构。执行前先运行 `scripts/runtime.py status`；状态为 `needs_init` 时先引导用户完成初始化。对本次操作涉及的每个概念运行 `scripts/runtime.py resolve --concept <key>`，只使用 Runtime 返回的目标 Data Source ID。读取该 Data Source 的实时 Schema，并在写入前运行 `scripts/runtime.py check-write` 校验本次属性、选项和 relation。

概念映射：`task, project`。

创建时必须让当前 Notion connector 将新页面的 parent 指向已解析的 Data Source；写入后回读确认 parent 和属性。若概念未找到、结构不兼容、候选不唯一或 connector 无法确认 parent，应停止该写入并说明原因，不得猜 ID、扫描无关空间或复制已有个人记录。以下正文中的数据库路径、字段名、选项和默认值若与用户实时 Schema 不一致，均视为示例而非要求；只有语义和字段类型明确匹配时才映射，否则询问或安全停止。仅读取本次任务所需的数据；不得将用户本地索引、凭据、页面 ID 或个人样例打包发布。

# Task Tracker — Notion 任务录入

## 输入

用户自然语言说一件要做的事，可能是：
- "晚上8点取快递"
- "明天下午3点面试"
- "记得交材料"
- 发来求职测评/面试截图

## 执行流程

### 1. 选择建页方式

在 Runtime 解析出的任务 Data Source 决定模板。简单待办优先使用用户已配置且经当前连接器核验的待办模板，阶段工作优先使用任务模板。只有能确认模板属于目标库、可读，且创建工具支持 `template_id` 时才应用。无法核实模板时，可直接在已核实的 Data Source 建页并写入任务正文。用户明确指定使用某个模板且无法核实时，说明缺口并请用户提供可访问的模板。

若连接器异步应用模板，使用其任务状态接口确认何时完成。返回页面 ID 后先核对 parent 与模板结构，根据实测结果局部填写正文。若创建状态不明确，先按返回 ID 或目标库中的唯一记录核对，再决定是否重试。

### 2. 解析任务信息

从用户话里提取：

| 字段 | 怎么提取 |
|---|---|
| **任务名** | 保留具体动作，通常以动词开头 |
| **任务日期** | 有具体日期时间就带时间（is_datetime=1）；只有日期就 is_datetime=0；没说日期就留空 |
| **是否待办** | 琐碎小事（取快递、交材料、突然想到的事）→ 是；正在推进的正经事 → 否 |
| **是否求职** | 提到面试/测评/笔试/公司招聘/求职 → 是 |

### 3. 判断情景标签

**普通任务：**
- 琐碎待办使用库中语义匹配的待办标签。模板已设置且用户没有要求额外标签时保留模板值。需要添加标签时，以完整数组保留模板已有且仍适用的标签。
- 正经事 → 情景留空（用户自己按场景加电脑/手机/学校等）

**求职任务（从截图或描述判断）：**
- 测评/AI面试/笔试 → `["⭕ 测评"]`
- 真人面试 → `["✌️ 面试"]`
- 如果是琐碎的求职小事（如"发简历"），同时加 `"☑️ 待办"`

### 4. 判断项目关联

当任务可能属于某个项目，先用 Runtime 解析 `project`，并检查任务 Relation 指向的目标。按实际 Schema 查询相关项目，只考虑仍在推进的项目。任务是某一项目阶段成果的组成部分且唯一匹配时才关联。多个候选会影响归属时可在回执里请用户确认。未匹配时先留空。

### 5. 预检并建页

用实际 title 字段填写任务名。用户给出日期时，按实时字段格式写入，保留日期与具体时点的区别。状态优先使用用户指定的有效选项，其次使用库中语义匹配的「收集」状态。库中没有对应选项时沿用经核实的模板默认值或留给用户决定。检查 title、本次属性、各选项和 relation 后创建。

依据用户提供的信息填写两个短段落。**为什么这个任务存在**用一句话说明这件事的目的。**相关背景**最多保留三条与执行有关的范围、约束或来源。用户只提供动作时可写「完成所述事项」，背景缺失时注明「用户未提供额外背景」。应用模板时只编辑对应占位项或追加缺少的段落，保留模板其余结构。

### 6. 验证

重新读取新任务，核实 parent、标题、本次提交的属性、项目关联与正文。模板尚未应用完成或内容无法核实，就报告具体状态。向用户返回已确认的新任务链接，并说明仍需确认的归属。

## 截图处理（求职）

当用户发来截图时：
1. 用 Read 读取截图，提取公司名、面试/测评时间、方式（线上/线下）、链接
2. 任务名格式：`<公司名> <面试/测评>`，如"字节跳动 一面"
3. 如果截图里有具体时间，填入任务日期（is_datetime=1）
4. 情景按规则选"✌️ 面试"或"⭕ 测评"
5. 按项目关联规则匹配活跃项目，确认唯一归属后再关联

## 不碰

- **优先级**：不自动设
- **公式字段**（提醒、经验、金币、跃点、血量、游戏化概览等）：Notion 自动算
- **按钮字段**（专注、休息、等）：用户自己点
- **完成日期**：完成时自动填

## 边界

- 用户没说日期时留空，并按实时可用的状态选项处理。
- 判断不准是不是求职 → 问一下用户
- 截图信息不全（没公司名/没时间）→ 提取能提取的，缺的问用户
