# Rhythm Revision

Use this when revising an existing draft or after creating the first draft.

## Paragraph Function Diagnosis

Before rewriting a paragraph, answer:
- What is this paragraph's function?
- What is its relationship with the previous paragraph?
- What is its relationship with the next paragraph?
- What is the biggest problem now?
- Should it be kept, compressed, rewritten, deleted, or moved?

Common paragraph functions:
- strong judgment opening
- daily phenomenon
- first problem drilldown
- mechanism explanation
- root cause drilldown
- method/action
- light product bridge
- closing echo

## Question-Driven Progression

Use a named creator's progression only when the user explicitly requests that reference. Learn the reasoning movement, never copy the wording or turn it into the account's permanent default.

A useful general chain is:

```text
You think the problem is A.
But the real problem is B.
Why does B happen?
Because the deeper issue is C.
So the answer is not D.
It is E.
```

Each paragraph's conclusion should naturally become the next paragraph's question.

Useful transitions:
- 为什么会这样？
- 更麻烦的是：
- 问题还不止于此。
- 这就解释了为什么。
- 所以真正缺的不是 X，而是 Y。
- 到这里，问题就很清楚了。
- 这才是很多人真正卡住的地方。

Avoid stiff transitions:
- 接下来我们讲
- 更重要的是
- 此外
- 还有一点
- 下面进入方法
- 总结一下

## Repetition Detection

Check three repetitions:

1. Information repetition: the same fact or scene appears again.
2. Judgment repetition: the same conclusion appears in different wording.
3. Function repetition: two paragraphs do the same job.

When repeated, choose one:
- delete
- compress into one sentence
- change angle
- move later
- keep but change function

## Abstract Concept Translation

Translate abstract concepts immediately into lived language.

Concepts that need translation:
- system
- context
- growth context
- business context
- accumulation
- compounding
- personal asset
- AI growth brain
- second brain
- knowledge base
- workflow
- long-term understanding

Example:

Do not only write:

> 普通人也需要成长上下文。

Translate it:

> 它要知道你最近在推进什么，过去为什么总是半途而废，哪些问题一直困扰着你。

## Product Bridge

The product must appear as the natural result of an unresolved problem.

Do not drop a product name into the paragraph before the unresolved reader problem has naturally created the need for it.

Prefer a bridge that explains why the current live product or method exists, using naming and intensity drawn from `commercial_positioning`, relevant `product` records, and the user's request. When named promotion is not authorized, use truthful category-level wording from those sources rather than a fixed replacement phrase.

After mentioning the product, return to the reader's change.

## Voice Calibration

Revise against the temporary style card built for this run, not a fixed persona embedded in the Skill.

Priority order:

1. explicit user instructions for this article;
2. current `commercial_positioning` and relevant `user_profile` evidence;
3. recurring signals in the selected `style_corpus` examples;
4. article type and reader-flow needs.

Preserve only patterns supported by those sources: first-person distance, sentence length, paragraph density, judgment intensity, story density, transitions, opening and ending habits, preferred language, and expressions to avoid.

Do not average the entire corpus into a generic voice, imitate one article mechanically, or assume a named creator, audience, vocabulary list, or commercial tone remains permanently valid.
