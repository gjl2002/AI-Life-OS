## 1. 运行定位

信息源日报只回答：

> 我主动关注的这些来源，在当前时间窗口内出现了什么值得理解的内容？

它不回答“整个行业今天发生了什么”。当用户要求公共趋势、全网热点、竞品扫描或研究补充时，说明这属于另一个研究任务，不要把外部来源静默混入本日报。

默认窗口为滚动过去 24 小时。用户指定自然日、日期区间或其他窗口时遵从用户要求，并使用用户或运行环境的时区。

## 2. 首次连接

默认首次运行需要两个准确的云端 Notion 数据库链接：`信息源`和`信息日报`。只有用户明确要求仅预览时，才只需要`信息源`链接。

如果用户只给出名称且工作区存在重名数据库，先请求准确链接，不进行大范围猜测。不要把某个公开模板的固定 ID 当作用户数据库。

根据模式获取：

- `信息源`：必需。
- `信息日报`：默认运行必需；仅预览时不需要。
- `概念库`：只有用户主动启用概念沉淀时需要。

连接完成后仍应在每次写入前读取实时 schema，因为用户可能修改字段。

## 3. 数据库语义要求

### 信息源数据库

必须能够识别：

| 语义 | 常见字段名 | 要求 |
| --- | --- | --- |
| 来源名称 | 名称、Name、Title、来源名称 | 必需 |
| 关注状态 | 关注状态、Status、Following、启用 | 必需 |
| 来源网址 | 首选网址、网址、URL、Feed、RSS、Website | 至少一个 |

可以按需使用：

- 备用网址或次选网址；
- 来源平台或类型；
- 语言；
- 标签；
- 内容风格；
- 更新频率；
- 简介。

先读 schema 再映射语义。若同一语义对应多个字段且无法确定，向用户确认。不要自动创建字段、状态值或关系记录。

### 信息日报数据库

写回时至少需要：

- 标题；
- 日期；
- 正文承载位置。

如果存在`核心判断`、`行动建议`、`主题`等属性，可以写入对应内容；不存在时保留在正文，不为了 Skill 修改数据库结构。

### 概念库

只要求能够保存：

- 概念名称；
- 简明解释；
- 来源名称；
- 来源链接；
- 与用户的关系或相关内容。

字段命名可以不同，以实时 schema 的语义为准。

## 4. 来源边界

日报候选池严格等于：

```text
云端信息源数据库
∩ 关注状态为启用
∩ 当前时间窗口内有已验证更新
```

不得自动加入：

- 官方 AI 公司新闻；
- 公共新闻网站；
- 热门榜单；
- GitHub Trending；
- 论文聚合站；
- Skill 作者的个人关注源；
- 模型凭常识推荐的来源。

如果上述来源本来就在用户关注列表中，则按普通关注源处理。

允许打开关注内容中的原始公告、论文、产品页面或引用链接进行事实核实。核实链接不自动成为独立日报条目，也不改变来源边界。

## 5. 时间与核验

### 核验优先级

1. RSS 或 Atom feed；
2. 来源官方提供的订阅地址；
3. 原始内容页面；
4. 频道页、作者页或公开接口；
5. 当前可验证的描述、摘要或文字稿。

### 覆盖状态

每个关注源只能标记为：

- `有已验证更新`：获得标题、链接和可信发布时间，且位于时间窗口内。
- `已验证暂无更新`：当前成功读取，并确认时间窗口内没有新内容。
- `未能验证`：当前读取失败、发布时间不清、反爬、网络错误，或只能获得旧缓存。

旧缓存只能帮助理解历史，不得证明实时无更新。

### 内容核验

- 每个日报条目保留原始链接。
- 长文或视频无法取得完整正文时，说明判断依据只有标题、简介或摘要。
- 区分来源事实、来源观点和日报综合，不把综合推断伪装成原文结论。
- 相同事件被多个关注源重复发布时合并处理，保留真正增加理解的差异。

## 6. 报告结构

### 今日核心判断

用一至数段说明：

- 今天新增是丰富、有限还是没有；
- 多个来源共同出现的主要信号；
- 对用户本次关注重点的意义；
- 来源覆盖是否完整；
- 今天最值得做的一件小事。

### 信息源读取覆盖

列出：

- 已验证且有更新；
- 已验证暂无更新；
- 未能验证及原因。

### 今日新增

每条至少包含：

- 来源；
- 标题；
- 链接；
- 发布时间；
- 发生了什么；
- 为什么值得注意。

### 值得深看

只放值得用户投入完整阅读或观看时间的内容。内容不足时省略，不要求固定数量。

### 可以学习

提取可复用的概念、方法、表达方式或工作流。

### 可以收藏

保留未来可能用于创作、决策、系统设计或实践的素材。

### 对我的启发

结合用户在本次请求中主动给出的关注重点组织启发。没有个性化上下文时，只基于来源内容说明可能用途，不推断用户的商业定位、人生目标或身份。

### 今日行动建议

给零至三条当天可以完成的小行动。没有可靠行动时可以不写，不把阅读清单包装成行动。

### 概念库更新

仅在概念库已启用时出现。说明创建、更新或没有合格概念的原因。

## 7. 写回规则

普通调用和自动日报默认都写回`信息日报`。只有用户明确说“只预览”“不要写入”或语义等价表达时才跳过写回。

默认写回时：

1. 读取日报数据库实时 schema；
2. 使用日期、报告类型和规范化标题检查同日重复；
3. 同日页面存在时优先更新，不重复创建；
4. 先完成正文草稿并检查结构与来源链接；
5. 只写入目标属性和正文，不覆盖无关内容；
6. 写入后重新读取属性与正文；
7. 报告实际页面和任何未验证来源。

无法定位`信息日报`、无法确认 schema 或回读失败时，不声称写入成功，也不静默降级为仅预览。应说明阻塞并请求正确数据库链接或权限。

## 8. 概念库规则

概念库不是日报的必需依赖。

只有满足全部条件时才建议写入：

- 能在多个场景中复用；
- 有可靠来源链接；
- 能帮助未来理解、表达或实践；
- 不是一次性专有名词；
- 与现有概念相比有明确新增。

写入前搜索同名、别名和近似概念。优先更新原页面，并保留来源和本次新增理解。

## 9. 失败处理

| 情况 | 是否继续生成 | 是否允许写回 | 处理 |
| --- | --- | --- | --- |
| Notion 无法访问 | 否 | 否 | 说明连接失败 |
| 关注源数据库无法读取 | 否 | 否 | 请求正确链接或权限 |
| 关注列表为空 | 是 | 视用户要求 | 生成配置提示，不制造内容 |
| 所有来源当前无法验证 | 否 | 否 | 列出失败原因 |
| 部分来源无法验证 | 是 | 是 | 明确披露覆盖缺口 |
| 已验证但没有新增 | 是 | 是 | 生成简短无新增日报 |
| 日报数据库缺失或 schema 无法确认 | 可形成草稿 | 否 | 报告阻塞并请求正确链接或权限 |
| 概念库不可用 | 是 | 日报可写 | 跳过概念写入并说明 |

## 10. 自动化检查表

按顺序执行：

1. 读取自动化中已经确认的数据库链接和时间窗口；
2. 连接云端 Notion 并读取信息源实时 schema；
3. 查询启用的关注源；
4. 验证每个来源的当前覆盖状态；
5. 检查是否存在阻塞条件；
6. 只从已关注且已验证更新的来源建立候选池；
7. 去重、读取并核验内容；
8. 生成日报草稿；
9. 检查链接、覆盖说明和事实边界；
10. 读取日报数据库 schema 并检查同日重复；
11. 创建或更新日报；
12. 条件式更新概念库；
13. 回读日报和概念页面；
14. 报告写入状态、覆盖缺口和失败原因。

## 11. 最终自检

- 是否所有日报条目都来自用户关注源？
- 是否误把核实链接变成新的候选来源？
- 是否为每条信息保留了可点击来源？
- 是否正确处理时间窗口和时区？
- 是否把未能验证误写成无新增？
- 是否为了凑数量加入低价值内容？
- 是否使用了用户未提供的商业定位或个人假设？
- 普通调用是否已经写入并完成回读？
- 用户明确要求仅预览时，是否没有写入 Notion？
- 写回是否先查重并完成云端回读？
- 概念库是否真的被用户启用且达到准入条件？
