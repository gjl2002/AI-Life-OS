# 商业定位质量检查

## 所有输出

1. 是否先通过 `$ai-life-system-init` Runtime 解析唯一《商业定位》，再实时读取云端，而不是让用户重新介绍全部背景？
2. 人生定位是否只作为上游约束，没有被当作市场证明？
3. 客户、问题、场景、替代方案、价值机制和证据是否具体？
4. 已确认事实、初步洞察、待验证假设是否分开？
5. 是否只读取了当前阶段最需要的商业来源？
6. 是否引入当前证据之外的结论却没有标识？
7. AI、新工具或趋势是否只是机制，而不是完整定位？
8. 是否把详细用户研究、产品架构、内容生产或销售运营错误地留在本 Skill 内完成？

## 教练过程

1. 本轮是否只推进一个会改变定位判断的关键缺口？
2. 是否先回接已有事实与用户回答，再解释为什么重要并提问？
3. 主问题是否配有必要说明、例子或简短回答框架，而非泛泛发问？
4. 用户回答抽象时，是否追到了具体客户、场景、行为、原话、选择或结果？
5. 确认没有事实后，是否停止盘问并把缺口转成可验证假设？
6. 用户要求总结或判断现有资料时，是否直接给出有证据边界的分析，而非以教练身份拒答？
7. 对话是否自然推进，没有固定 A/B/C 入口、机械步骤标签或每轮“回复继续”的仪式？

## 商业定位地图门槛

- 冷用户能够认出自己和问题；
- 当前替代方案与切换触发真实存在；
- 价值机制与定位层产品假设可理解；
- POV 会导致具体选择，但不代替需求证明；
- 至少有一类客户、内容、咨询、销售、收入或持续市场信号；
- 差异会影响客户选择或结果；
- 明确仍然不知道什么以及何时重新校准。
- 明确对下游用户、产品和内容 Agent 的约束，但没有替它们完成详细执行。

不满足关键门槛时，降级为商业定位假设地图。

## 云端更新

- 最终结果只更新 Runtime 解析出的现有《商业定位》页面；
- 更新前执行 `check-page-write` 并实时重新读取页面；
- 更新前重新读取，保留仍有效的事实与证据；
- 不新建“个人商业地图”平行页面；
- 更新后回读核对。

## 禁止项

- 用“AI 赋能”“个人品牌”“长期主义”“成长型人群”作为完整定位；
- 编造客户案例、成交、收入、转化或对标数据；
- 把人生热爱直接等同于市场需求；
- 用强 POV 或宏观趋势替代客户和市场证据；
- 为了新颖创造冷用户无法理解的品类；
- 每次强制运行所有高级框架。
- 在商业定位中直接产出完整用户研究、产品架构、内容计划或销售 SOP。
