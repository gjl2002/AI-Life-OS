# 用户画像输出结构

以下结构服务于思考清晰度，不要求把空栏目填满。正式画像进入现有云端用户画像数据库，不创建平行资产。

## 正式用户画像

```markdown
# 用户画像：{画像名称}

## 1. 这个用户是谁
- 用户类型：
- 对应产品或场景：
- 核心任务 / JTBD：
- 适合与不适合：

## 2. 他在什么情况下开始寻找帮助
- 触发场景：
- 现实压力或代价：
- 最近一次典型行为：

## 3. 他真正想改变什么
- 功能结果：
- 情绪或身份结果：
- 判断成功的标准：

## 4. 他现在怎么解决，为什么没有解决好
- 当前替代方案：
- 已尝试方法：
- 失效点：
- 继续维持现状的原因：

## 5. 他为什么会购买，又为什么不会购买
- 购买触发：
- 值得付费的结果：
- 为什么会购买：
- 为什么不会购买：
- 价格、时间、信任或使用顾虑：

## 6. 什么建立信任，他会怎样表达问题
- 用户原话与来源：
- 信任来源：
- 容易触发的表达：
- 应避免的误解或压力：

## 7. 已经确认的事实、洞察与假设
- 已确认事实：
- 合理洞察：
- 待验证假设：

## 8. 分群与边界
- 是否需要分群：
- 与其他画像的区别：
- 不适合用户：

## 9. 对商业系统的影响与下游交接
- 对商业定位的修正或支持：
- 产品 Agent 需要继续验证：
- 内容与销售表达约束：
- 建议交给的下游 Skill：

## 10. 仍然需要验证什么
- 最大证据缺口：
- 下一步材料或访谈问题：
- 支持 / 推翻信号：

## 证据来源
- 来源、时间、用户身份与证据等级：
```

内部保留 `evidence-audit.md` 的证据矩阵。只有来源不确定、用户要求查看推理，或写回需要审计时，才展示完整矩阵。

## 用户画像假设

```markdown
# 用户画像假设：{临时名称}

## 1. 目前可能是哪类用户
## 2. 当前材料支持了什么
## 3. 还不能确认什么
## 4. 为什么现在不能作为正式画像
## 5. 下一步需要什么材料或访谈
## 6. 支持或推翻假设的信号
```

## 用户洞察阶段小结

```markdown
# 用户洞察阶段小结

## 本轮确认了什么
## 哪些仍然只是判断
## 当前最大的证据缺口
## 下一个聚焦问题或材料
```

## 多画像输出

只有差异会改变商业定位、产品、销售或交付时才拆分。可使用：

- 核心用户画像；
- 次级用户画像；
- 潜在但未验证用户画像；
- 不适合用户。

每组都要说明拆分依据，不用年龄、城市或职业差异制造装饰性分群。
