# Market Competition

Use this for market size, substitute analysis, win logic, and name occupancy.

## Substitute Types

Look for substitutes beyond direct competitors:

- manual workaround
- Notion template / Feishu template / spreadsheet
- ChatGPT project or prompt bundle
- course / bootcamp / community
- consultant / coach / done-for-you service
- existing content habit
- doing nothing

If users currently do nothing, explain what fear, pleasure, identity, or scene would make them start.

## Benchmark Sources

Use the user's benchmark databases when available:

- `对标产品`: product type, pricing, reference content, linked account/content, sales, priority.
- `对标内容`: benchmark messages, themes, platform, content performance, product mentions.
- `对标账号`: solved problems, target users, product system, conversion path, private-domain scale, positioning.
- `对标封面`: useful only when visual or sales-page packaging matters.

Borrow patterns, not copy. Separate competitor facts from inferred market lessons.

## Win Logic

A product can win through:

- sharper target user
- stronger trigger scene
- faster immediate satisfaction
- better proof/cases
- stronger content-to-product loop
- lower delivery friction
- better trust or privacy boundary
- better AI/private-context integration
- better name occupancy

Avoid saying "because it uses AI" as the win logic. AI must create a visible user advantage.

If current market, competitor, pricing, public product, or trend claims matter and internal benchmark records are stale or thin, use current web verification when available. If web verification is not performed, label the market judgment as `待验证假设`.

## Conditional Name Occupancy

Run this section only when naming, public category language, searchability, word of mouth, or product identity can change adoption.

Ask:

```markdown
当用户遇到这个问题时，会想到哪个名字:
当前名字:
问题-名字匹配:
是否容易被记住:
是否容易被说出来:
它召唤的情绪/画面:
它借到的文化资产:
是否有隔绝目标用户的风险:
是否过早暴露内部系统名:
用户会替它传播哪句话:
更好的名字方向:
```

Public naming should match the problem users remember. Read current `commercial_positioning`, relevant `product` records, and the user's explicit request before deciding reader-facing wording. Do not embed a permanent product name or replacement list.

If the name exposes an internal system/template before users understand the problem, mark name occupancy as weak and suggest public category language.

Score name occupancy higher only when the name is not merely accurate, but also easy to call, emotionally warm, culturally loaded, and tied to the problem users remember. A strong name is a cultural asset: users can say it, remember it, and use it to summon the product in the moment of need.

Do not confuse word-of-mouth with a slogan. Word-of-mouth means the product has an over-delivered moment that makes users naturally repeat a stable sentence. If no over-delivery point exists, mark the word-of-mouth sentence as a hypothesis and recommend an experience validation action.
