# 计时数据源与字段

先运行 `ai-life-system-init` 的 `scripts/runtime.py status`。用 `resolve --concept timer` 解析计时数据源。如果没有识别到语义，可按用户给出的链接确认真实源名，再用 `resolve --source <实际名称>` 复核。重名时确认唯一的目标；索引缺失或过期时，先检查初始化或重新绑定。

## 字段映射

| 语义 | 模板中的常见字段 | 用法 |
| --- | --- | --- |
| 活动名称 | 专注 | 当前的真实 title 字段 |
| 运行状态 | 状态 | 当前 Schema 中表达进行中和完成的状态或单选值，例如「专注」「完成」 |
| 开始时刻 | 开始时间 | 带时区的日期时间 |
| 结束时刻 | 结束时间 | 带时区的日期时间，结束和补记时使用 |
| 时间区间 | 记录时间范围 | 作为可选的日期范围。结束时提交完整的原开始与结束 |
| 活动类别 | 时间分类 | 按用户明确选择或当前可核实的分类填写；无法明确识别时留空 |

当平台用单个日期范围表达起止时，先核验它能同时支持开始、查询当前状态和结束。遇到关键字段或状态无法可靠映射时，报告受影响操作。可按需填写的分类与关联留给用户自己的结构决定。

## 可选关联

任务、习惯、书籍、笔记、信息或课程有直接关联字段时，可查找该字段真实指向的数据源。只核对与当前活动明确相关、尚未完成的已有条目，且候选唯一时才填写。多个候选影响记录归属时请用户选择，可以留空。关联前核验页面归属和 Runtime 的关系预检结果。已有的每日记录、每周复盘、积分及角色关联由原系统管理。

## 写入接口与回读

- 创建时使用当前连接器的 Data Source 父对象，并提交真实标题、状态及时间字段。模板只在用户已明确配置且工具支持时适用。完成时以同一条记录的原开始时间为准。
- 预检用 `check-write --data-source-id <真实ID> --operation create|update`。用 `--field` 传本次实际字段名，用 `--option` 传本次选项，例如 `状态=完成`。按宿主连接器的字段格式传值，并在一次更新中一起发送状态和结束信息。
- 回读核验父 Data Source、标题、状态、实际起止及本次填写的关联。时长、汇总和积分公式按只读值处理。页面归属或异步结果未确认时，保留可核实的回执和待查项，再决定后续动作。
