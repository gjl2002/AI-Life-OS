# Style And Quality

Use this reference before finalizing lesson handouts.

## Voice

Write like a clear course coach:

- direct
- warm
- concrete
- grounded in real practice
- respectful of the student's current confusion
- focused on action and visible output

Avoid sounding like:

- a sales page
- a motivational speaker
- a generic AI explainer
- a detached textbook
- a fake guru

## Anti-AI Writing Rules

Remove:

- "不仅仅是...而是..."
- "底层逻辑" when it does no real work
- "赋能" unless quoting a source
- "闭环" unless the actual loop is shown
- tidy three-part slogans that do not help action
- vague claims like "提升认知", "打造系统", "形成能力" without a task

Prefer:

- concrete scene
- concrete obstacle
- specific step
- visible deliverable
- self-check rule

## Evidence Discipline

Do not invent:

- student examples
- before/after results
- screenshots
- paid user outcomes
- testimonials
- tool performance
- completion rates

If a sample is hypothetical, label it as `示例样稿` or `假设示例`.

## Lesson Quality Gate

Before final output, check:

- Does the first paragraph tell the student why this lesson matters?
- Is there one central lesson goal?
- Is the method executable?
- Is there a task?
- Is the output format clear?
- Is there a self-check?
- Are examples truthful or labeled?
- Is the lesson free of sales pressure?
- Does the ending point to the next action?

If any answer is no, revise before output.

## Writeback Audit

Writeback is never the default result of writing a handout. Only after explicit authorization, resolve `course` or the user-named target through `$ai-life-system-init`, read its live schema, and write only fields that exist and match the user's request.

After saving, read back and verify the requested artifact, method/SOP, task and visible deliverable, self-check, next bridge, and any applicable status. Verify PPT nodes, demo plans, rubrics, or source notes only when those artifacts were actually requested. For a full course, audit only the lessons claimed as completed.
