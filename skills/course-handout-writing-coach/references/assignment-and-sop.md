# Assignment And SOP Design

Use this reference when designing student tasks, SOPs, worksheets, prompts, and feedback rubrics.

## Assignment Contract

Every assignment should include:

- purpose: why this task exists
- input: what the student needs before starting
- steps: what to do
- output: what to submit or produce
- time estimate: how long it should take
- self-check: how to know it is acceptable
- feedback rule: how the coach or system will review it
- system destination: where the artifact is saved and how the next lesson or review will call it

## SOP Rules

A good SOP is:

- specific enough to execute
- short enough to finish
- tolerant of beginner mistakes
- connected to a visible output
- reviewable by another person or AI

Avoid SOPs that depend on taste, vague "thinking deeply", or invisible effort.

## AI Prompt Template Rules

When a lesson includes prompts:

- name the prompt's purpose
- define required inputs
- include the prompt
- show expected output
- add a repair prompt or troubleshooting rule

Prompts should not replace student judgment. Add a "what to check manually" section.

## Feedback Rubric

Use a 3-level rubric by default:

| 维度 | 需要重做 | 合格 | 优秀 |
| --- | --- | --- | --- |

Common dimensions:

- matches the target user/problem
- has concrete input material
- produces a visible artifact
- can be reused next time
- is simple enough to continue
- reflects the student's own context

## Common Assignment Failures

Watch for:

- output is a vague reflection, not a deliverable
- task is too big for one lesson
- prompt creates generic content
- student cannot tell whether they did it right
- assignment requires unavailable materials
- feedback would be too expensive to deliver at scale
