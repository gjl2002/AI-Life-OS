## 用户自己的 Notion 接入

本 Skill 使用 `$ai-life-system-init` 定位用户自己的 Notion 结构。执行前先运行 `scripts/runtime.py status`；状态为 `needs_init` 时先引导用户完成初始化。对本次操作涉及的每个概念运行 `scripts/runtime.py resolve --concept <key>`，只使用 Runtime 返回的目标 Data Source ID。读取该 Data Source 的实时 Schema，并在写入前运行 `scripts/runtime.py check-write` 校验本次属性、选项和 relation。

概念映射：`life_moment, goal, personal_story`。

创建时必须让当前 Notion connector 将新页面的 parent 指向已解析的 Data Source；写入后回读确认 parent 和属性。若概念未找到、结构不兼容、候选不唯一或 connector 无法确认 parent，应停止该写入并说明原因，不得猜 ID、扫描无关空间或复制已有个人记录。以下正文中的数据库路径、字段名、选项和默认值若与用户实时 Schema 不一致，均视为示例而非要求；只有语义和字段类型明确匹配时才映射，否则询问或安全停止。仅读取本次任务所需的数据；不得将用户本地索引、凭据、页面 ID 或个人样例打包发布。

## 类型判断规则

从用户自然语言判断：

| 类型 | 判断依据 | 颜色 |
|---|---|---|
| 高光 | 成就感、被夸奖、获奖、挑战成功、开心自豪 | green |
| 低谷 | 失败、挫折、身心俱疲、痛苦、焦虑低落 | red |
| 转折 | 做出重要决定、人生方向改变、换赛道、关键选择 | blue |
| 觉察 | 突然想明白一个道理、认知升级、自我反思 | purple |
| 体验 | 第一次尝试、新鲜经历、旅行、吃饭、日常体验 | brown |

用户说了类型词（"这是个高光时刻""我好低谷"）就直接用；没说就根据内容推断，推断不准选最接近的并在报告里说明。

## 执行流程

### 1. 直接新建记录

在 Runtime 已解析的用户 Data Source 中直接创建新记录；不复制现有记录。


### 2. 判断字段

| 字段 | 怎么填 |
|---|---|
| 事件描述 | 用户说的核心事件，一句话简述（不超过30字） |
| 类型 | 按上方规则判断 |
| 记录日期 | 用户说"今天/刚才"→今天；"昨天"→昨天；有具体日期就用 |
| 备注 | 用户详细描述的内容；没说就留空 |

### 3. 关联相关目标

用 `notion_ai_search`（data_source_url=目标数据源）搜索与事件内容相关的目标：
- **找到明显匹配的** → 填入 `相关目标` relation（URL 数组）
- **没找到/不确定** → 留空，不强行关联

判断标准：这个时刻是不是在为某个长期目标做里程碑？比如"粉丝到1万"对应"成为AI博主"目标。

### 4. 关联个人故事

用 `notion_ai_search`（data_source_url=个人故事数据源）搜索：
- **明显属于某个故事线** → 填入 `个人故事` relation
- **不确定** → **不关联，留空**（这是与目标的关键区别：个人故事不强行关联）

### 5. 一次性 update

```json
{
  "事件描述": "<一句话简述>",
  "类型": "<高光/低谷/转折/觉察/体验>",
  "date:记录日期:start": "YYYY-MM-DD",
  "date:记录日期:is_datetime": 0,
  "备注": "<详细内容或null>",
  "相关目标": ["<目标页面URL>"],
  "个人故事": ["<当前用户个人故事页 URL>"]
}
```

新页面只写本次记录明确提供的值；未提供的可选字段留空，不沿用其他记录的属性或正文。

### 6. 验证

`notion_fetch` 新记录，确认：
- parent-data-source = 人生时刻
- 事件描述、类型、日期落库
- 旧关联已清理

向用户报告填了什么，关联了哪个目标。

## 不碰

- **概览**（formula）：Notion 自动算
- **页面正文**：默认留空
