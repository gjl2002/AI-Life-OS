## 用户自己的 Notion 接入

本 Skill 使用 `$ai-life-system-init` 定位用户自己的 Notion 结构。执行前先运行 `scripts/runtime.py status`；状态为 `needs_init` 时先引导用户完成初始化。对本次操作涉及的每个概念运行 `scripts/runtime.py resolve --concept <key>`，只使用 Runtime 返回的目标 Data Source ID。读取该 Data Source 的实时 Schema，并在写入前运行 `scripts/runtime.py check-write` 校验本次属性、选项和 relation。

概念映射：`food_log`。

创建时必须让当前 Notion connector 将新页面的 parent 指向已解析的 Data Source；写入后回读确认 parent 和属性。若概念未找到、结构不兼容、候选不唯一或 connector 无法确认 parent，应停止该写入并说明原因，不得猜 ID、扫描无关空间或复制已有个人记录。以下正文中的数据库路径、字段名、选项和默认值若与用户实时 Schema 不一致，均视为示例而非要求；只有语义和字段类型明确匹配时才映射，否则询问或安全停止。仅读取本次任务所需的数据；不得将用户本地索引、凭据、页面 ID 或个人样例打包发布。

# Food Tracker — Notion 饮食记录

## 数据库

- **目标数据源**：以 Runtime 对 `food_log` 的解析结果为准

## 执行流程（照此执行）

### 1. 直接新建记录



### 2. 分析

有照片→下载并 Read 读图；纯文字→从描述分析。
输出：名称/食物/餐型/健康评估/总重量/卡路里/蛋白质/脂肪/碳水。

### 3. 上传图片

1. 拿照片直链（不要用会 302 的 aka 短链）
2. `notion_create_attachment` → `file_upload_id`
3. 填到「图片」属性

### 4. 一次性 update 属性

```json
{
  "名称": "<餐名>",
  "食物": "<食物明细>",
  "原始描述": "<用户原话>",
  "餐型": "午餐",
  "健康评估": "<AI 健康评价>",
  "记录方式": "拍照",
  "总重量 g": 500,
  "卡路里 kcal": 600,
  "蛋白质 g": 25,
  "脂肪 g": 20,
  "碳水 g": 80,
  "摄入比例 %": 100,
  "date:时间:start": "YYYY-MM-DDTHH:mm:00+08:00",
  "date:时间:is_datetime": 1,
  "图片": [{"type":"file_upload","file_upload":{"id":"<file_upload_id>"}}]
}
```

新页面只写本次记录明确提供的值；未提供的可选字段留空，不沿用其他记录的属性或正文。

### 5. 验证

fetch 新记录，确认 parent-data-source = 饮食记录、属性落库、图片挂载。向用户报告。

## 核心规则

- **时间**：默认现在；照片有拍摄时间且在过去10天内→按拍摄时间补记录
- **摄入比例**：默认 100；用户说"吃了一半"→按实际填数字
- **不做健康数据联动**：卡路里是 AI 估算，仅作记录参考

## 不碰

- 公式字段（颜色/热量评级/营养概览/营养提醒）
- 饮食库无 relation 字段，不需要关联每日记录/每周复盘

## 已知坑

- 标题「名称」被日期占位锁死时，餐名写进「食物」字段兜底
