# 习惯打卡

通过 [数据源与字段](references/notion-runtime.md) 使用 `ai-life-system-init` 定位用户自己的习惯定义、打卡记录和每日记录数据源。先确认用户要记录、查询、新建习惯，还是补挂每日记录。普通对话、进度查询和连接检查只读。专注计时交给 `focus-timer-tracker`。

## 记录或补打

1. 从用户话里提取习惯名、日期或时间、明确给出的次数。按用户已确认或运行环境可确定的时区解释今天、昨天和上周。实时打卡默认用当前时刻，补打只给了日期时保存日期。无法确定归属日期时询问。
2. 在习惯定义源按名称匹配，优先使用唯一的进行中条目。仍有多个匹配时请用户选择。找不到时给出匹配结果。只有归档或失败条目时说明其状态。新建或恢复习惯需要用户明确指示。
3. 查询目标习惯在该本地日期的已有打卡。每次实际打卡各建一条，默认编号为当日已有打卡条数加一。用户明确指定次数时按其指示写，在回执中注明与当前记录条数的差异。同一习惯在两分钟内已有记录且无法判断是否重复时，先问是否又完成了一次。对仅有日期的记录，保留日期精度。若一次创建返回超时或结果未知，回查已有记录并确认结果后再决定是否重试。
4. 在打卡记录源创建 `习惯名 · 第N次`，填写日期、已打卡标记并关联习惯。找得到唯一且对应同一日期的每日记录时一并关联。确认没有该日记录时照常打卡，说明每日记录尚未关联。遇到多条同日候选且无法确认时，让用户选定后再挂接。需要为未关联的旧打卡补挂时，先核对旧条目和对应日期，再按用户指示更新原条目。
5. 回读新建或更新的页面，核对标题、本地日期或时刻、状态以及本次写入的关联。相关双向字段存在且可读时，也从习惯或每日记录侧核对新关联。回复本次打卡结果及用户关心的次数，区分用户指定的第几次和实际记录条数。坏习惯按用户明确的打卡语义处理，例如为当天达成的限制目标打卡。

## 查询与新建习惯

- 统计按打卡记录条数，精确匹配习惯关联的页面 ID。默认按本地周一到周日或当地日历月统计，回复注明日期范围。连续天数或完成率仅在有明确口径且能从可核验记录得出，或公式返回实际值时报告。
- 只有用户明确要求新建习惯时才创建定义，先检查是否已有同名条目，再使用实时 Schema 支持的选项。模板支持时可沿用原默认值：进行中、好习惯、目标 21 次、按月数、标记 √。用户说已完成并要求顺便打卡时，核对新定义后按记录流程写第一条。
