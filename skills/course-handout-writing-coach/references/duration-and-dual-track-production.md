# Duration and Dual-track Production / 时长与双轨生产

Read this reference only when the user requests a timed lesson, instructor script, PPT, live demo, or coordinated delivery package. Do not apply it to an ordinary handout, workbook, SOP, or bounded revision.

## Delivery Budget

Set a time budget before drafting. A 60-minute teaching lesson may include:

| Teaching job | Typical share | What it requires |
| --- | --- | --- |
| Recognition / opening | 10–15% | scene, question, interaction |
| Causal explanation | 20–30% | mechanism, contrast, boundary |
| Case / demonstration | 20–30% | worked example or live demo |
| Method / asset | 15–25% | steps and decision points |
| Learner work / assignment | 10–20% | instructions, sample, self-check |
| Closure | 5–10% | return to opening problem and next handoff |

Estimate spoken words only after budgeting these jobs. Mandarin delivery rate varies; account for pauses, audience interaction, screen reading, and demos. Do not fill time with abstract explanation.

## Conditional 90-minute Live Lesson Contract

Only when the user explicitly requests a 90-minute live lesson, the draft must include a time-coded run of **85–95 minutes**, including a 3–5 minute delivery buffer. It is not sufficient to label sections `约 X 分钟`; each segment needs a teaching job, evidence, and a planned interaction or delivery mode.

| Live segment | Target minutes | Minimum substantive content |
| --- | ---: | --- |
| Recognition and entry | 8–12 | one recognisable scene, learner question, old-path contrast |
| Root mechanism | 15–20 | causal explanation, at least one contrast or non-example |
| Core method / model | 15–20 | a full decision framework with criteria and boundary |
| Case + demonstration | 18–25 | one worked case plus a live/system demo or second contrast case |
| Guided practice / assignment | 12–18 | learner completes a bounded asset; include filled sample and self-check |
| Closure / handoff | 5–8 | return to opening question, commitment, next lesson's use of asset |

The lesson must contain at least **three complete teaching units**:

```text
real scene → old interpretation → causal mechanism → new judgment
→ method / decision → example or demonstration → bounded learner action
```

Do not count a slogan, an agenda page, a tool tour, or repeated explanation as a teaching unit. Do not pad time with a longer introduction.

## Timing Verification

Before declaring a 90-minute script deliverable:

1. Publish a `分钟运行表`: page/segment, teaching job, planned minutes, proof/demo, learner activity, and contingency cut.
2. Calculate separately: spoken explanation, participant interaction, live demonstration, learner work, and buffer.
3. Run a timed read-through or rehearsal when possible. Until that has occurred, call the duration an **estimated 90-minute run**, not a guaranteed live duration.
4. If the read-through is under 80 minutes, repair with a better case, comparison, demonstration, or guided practice—not generic theory.

## Optional Coordinated Artifacts

Produce only the artifacts required by the current delivery request:

1. **Instructor script**: spoken language, pauses, prompts, transitions, and demo cues.
2. **PPT rhythm board**: page role, screen sentence/visual, spoken purpose, evidence, transition.
3. **Live-demo plan**: starting state, inputs, actions, expected output, contingency, and exact lesson point.
4. **Learner action pack**: task, input, steps, submission format, sample, self-check, rubric, and next-lesson use.

When a script and deck are both requested, every major script section must map to a screen or intentionally be screen-free. Every PPT page must have one dominant teaching job; never create a deck by slicing paragraphs from a manuscript.

## PPT Treatment When A Deck Is Requested

If the user requests a deck but not a visual style, use a simple black background with white text as the low-cost default. Each page carries one dominant sentence, contrast, or simple mechanism map; the spoken script provides the detail. Use screenshots only as evidence or live-demo handoff, not decoration. Do not generate a deck merely because a handout is being written.
