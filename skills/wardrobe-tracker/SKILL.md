## 用户自己的 Notion 接入

本 Skill 使用 `$ai-life-system-init` 定位用户自己的 Notion 结构。执行前先运行 `scripts/runtime.py status`；状态为 `needs_init` 时先引导用户完成初始化。对本次操作涉及的每个概念运行 `scripts/runtime.py resolve --concept <key>`，只使用 Runtime 返回的目标 Data Source ID。读取该 Data Source 的实时 Schema，并在写入前运行 `scripts/runtime.py check-write` 校验本次属性、选项和 relation。

概念映射：`wardrobe, relationship_circle, gift`。

创建时必须让当前 Notion connector 将新页面的 parent 指向已解析的 Data Source；写入后回读确认 parent 和属性。若概念未找到、结构不兼容、候选不唯一或 connector 无法确认 parent，应停止该写入并说明原因，不得猜 ID、扫描无关空间或复制已有个人记录。以下正文中的数据库路径、字段名、选项和默认值若与用户实时 Schema 不一致，均视为示例而非要求；只有语义和字段类型明确匹配时才映射，否则询问或安全停止。仅读取本次任务所需的数据；不得将用户本地索引、凭据、页面 ID 或个人样例打包发布。

# Wardrobe Tracker — Notion 衣橱录入

## 数据库

字段与选项可参考 [references/database-schema.md](references/database-schema.md)，但每次操作必须以 Runtime 返回的用户实时 Schema 为准。

## 输入解析

| 字段 | 来源 |
|---|---|
| 名称 | 商品名/用户描述 |
| 品牌 / 品类 / 类别 / 颜色 / 尺寸 / 入手价 | 商品链接、订单/商品截图、用户描述（三者任一或组合） |
| 获取方式 | 用户明确提供时填写；无法判断时询问或留空，不猜购买方式 |
| 获取日期 | 用户给具体日期；相对日期（上周/前天等）用当前日期推算成 YYYY-MM-DD |
| 季节 / 场景 | 按「判断规则」自动填 |
| 图片 | 商品图/订单截图/用户提供图片 |

缺任何关键信息（尤其获取方式、获取日期）时向用户确认，不猜。

## 最稳定执行流程（务必照此，勿走捷径）

> 目标：生成「已拥有」视图可见、属性齐全、不产生垃圾页的正常记录。

### 0. 判断与前置
- 从链接/截图/描述中识别各字段；无法识别就一次性问清（缺什么问什么）。

### 1. 直接新建记录
- 在 Runtime 已解析的用户 Data Source 中直接创建新记录；不复制现有记录。
- 等待创建结果返回，保存新记录 page_id。

### 2. 上传图片
- 用 `notion-create-attachment`，`source_url` = 商品图/订单截图直链（本地图先 `FileBatchUpload` 拿 URL）。
- 拿到 `file_upload_id`。
- 无图则跳过，交付时说明"图片待补"。

### 3. 检查字段选项
- 依据实时 Schema 读取当前选项。只使用已有且语义匹配的值。
- 若用户所需值没有匹配选项，不要自动修改数据库 Schema；先询问用户是否要调整结构，或留空并说明。

### 4. 一次性 update 属性
- `notion-update-page`（`update_properties`），`page_id` = 新记录 page_id。
- 填：`名称`、`品牌`、`品类`、`类别`、`颜色`、`尺寸`、`入手价`(number)、`获取方式`、`date:获取日期:start` + `date:获取日期:is_datetime:0`、`季节`(数组)、`场景`(数组)、`状态`、`图片`、`相关人物`(可选)。
- 图片属性格式：`"图片":[{"type":"file_upload","file_upload":{"id":"<file_upload_id>"}}]`。
新页面只写本次记录明确提供的值；未提供的可选字段留空，不沿用其他记录的属性或正文。
- 状态只有在用户 Schema 存在语义匹配选项且规则明确时才填；否则留空或询问。

### 5. 验证
- `notion-fetch` 新记录，确认 `parent-data-source` = 衣服数据源、属性全部落库、图片已挂载。
- 向用户报告录入结果，主观字段留空。

## 判断规则

- 季节：羽绒服→冬；茄克/外套/针织衫/毛衣/卫衣→春秋；短袖/短裤→夏；长裤/休闲裤→春夏秋；长袖→春秋。
- 场景：依据用户实时 Schema 和明确上下文填写；不能确认时留空。
- 颜色按「临近色为主」归并：褐/米/驼/咖啡→`棕色`；深蓝→`蓝色`；墨绿→`绿色`。
- 品类/类别：茄克→`外套`/`外套`；针织衫/毛衣→`毛衣`/`上衣`；长裤→`休闲裤`(需新增)/`裤子`；短袖→`短袖`/`上衣`；卫衣→`卫衣`/`上衣`；运动鞋/板鞋→对应/`鞋子`；斜挎包→`斜挎包`/`配饰`。

## 不碰

- `喜爱程度`、`常穿程度`（用户主观，置空待填）。
- 公式字段：`使用标签`/`信息汇总`/`基础标签`/`总日均`/`星级评分`。
- 按钮字段：`同步至礼物`。
- 关联：`礼物`、`穿搭`（除非用户明确要求关联）。

## 边界

- 品牌/品类不在选项里 → 不自动改 Schema；询问用户或留空并说明。
- 图片直链失效/上传失败 → 留空并告知。
- 信息不全（缺价格/日期/获取方式）→ 填已知项，缺的向用户确认后补。
