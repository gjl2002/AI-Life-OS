# Expense Tracker — Notion 记账

## 用户自己的 Notion 接入

本 Skill 使用 `$ai-life-system-init` 作为结构底座。开始前先运行其 `scripts/runtime.py status`；若为 `needs_init`，请用户运行 `$ai-life-system-init` 后再继续。按场景用以下 concept key 解析用户的 Data Source：

- 普通支出：`expense`；普通收入：`income`；账户间转移：`transfer`；报销：`reimbursement`。
- 分类：`expense_category`、`income_category`；账户：`financial_account`；订阅：`subscription`。
- 交易报表（仅当实际 Schema 中存在相应 relation 时）：`daily_report`、`weekly_report`、`monthly_report`、`yearly_report`。
- 旅行联动（仅当前交易确属旅行支出时）：`travel`。

通过 `runtime.py resolve --concept <key>` 获取真实目标。多候选时结合当前场景筛选，仍不唯一就问用户；`not_found`、结构不兼容或未连接时，不得回退到固定 ID。读取实时 Schema，并在每次创建或更新前用 `check-write` 校验本次全部字段与选项。所有新交易都直接在解析出的 Data Source 创建；禁止复制任何已有真实记录或用户页面。写入后回读核验。

首次遇到账户时确认本笔应使用的账户；在当前对话中复用用户刚确认的默认值。Runtime 目前不持久保存账户偏好，因此新对话中没有用户偏好记录时重新确认。只查询完成当前动作所需的账户、分类、订阅或报表页面。

## 数据库

数据库名称、Data Source ID、用户确认的默认账户和分类选项都以用户当前 Notion Schema 及用户确认结果为准；本 Skill 不内置任何账号、页面、数据库 ID 或默认分类。

## 场景覆盖

| 场景 | 目标概念 | 执行边界 |
|---|---|---|
| 收入 | `income` | 仅在用户收入库存在时记录 |
| 支出 | `expense` | 可选分类与报表关联 |
| 转账 | `transfer` | 用户账户间转移，不归为收支 |
| 报销 | `reimbursement` | 只使用用户当前 schema 支持的字段 |
| 订阅 | `expense`、`subscription` | 先按支出记录；产品关联与周期为可选 |
| 分类 | `expense_category`、`income_category` | 只匹配用户自己的分类 |
| 账户 | `financial_account` | 使用用户指定或已确认的默认账户 |
| 报表 | `daily_report`、`weekly_report`、`monthly_report`、`yearly_report` | 只在 relation 存在且能唯一匹配时挂靠 |

公式汇总类数据不直接录入；除非用户的 Notion 结构实际支持，不承诺自动汇总。

## 核心规则（省心 + 保留分析）

1. **账户：使用用户已确认的默认账户；若未确认或查到多个账户，询问用户。** 不套用作者或示例系统中的账户。
2. **二级分类：若目标数据库有该字段则尽量匹配。** 只能从用户自己的分类库/选项中精确匹配；没有明确候选时留空，并在回读报告中标出"未归类"。
3. **金额：必填。** 从自然语言提取（`¥` / `元` / `块` / 纯数字）。
4. **日期：默认今天**，用户指定则按指定。**API 写入必须是 ISO 格式 `YYYY-MM-DD`**（如 `2026-09-23`；Notion 界面显示为 YYYY/MM/DD，但写入传 ISO），配合 `date:日期:start` + `date:日期:is_datetime`=0。
5. **备注：可选**，用户说了才填。

### 支出字段

| 字段 | 怎么填 |
|---|---|
| 新支出（标题） | 事由，如"午饭""打车""买咖啡"；没给就用"一笔支出25元" |
| 金额 | 必填，单位元 |
| 日期 | 默认今天 |
| 账户 | 用户确认的默认账户或本笔指定账户 |
| 二级分类 | 在用户自己的支出分类库搜索明确匹配项；没有则留空并说明 |
| 备注 | 用户说才填 |

### 收入字段

| 字段 | 怎么填 |
|---|---|
| 新收入（标题） | 事由，如"奖学金""生活费""红包"；没给用"一笔收入XX元" |
| 金额 | 必填，单位元 |
| 日期 | 默认今天 |
| 账户 | 用户确认的默认账户或本笔指定账户 |
| 二级分类 | 在用户自己的收入分类库搜索明确匹配项；没有则留空并说明 |
| 备注 | 用户说才填 |

### 转账场景（账户间转移资金，非收支）

触发词：`转/转入/转出/转账/把X转到/存起来/定存/理财转入/存钱`。表达的是**自己账户之间转移钱**（如把资金从一个账户转到另一个账户），**不记入支出/收入**，单独写进「转账」库。

| 字段 | 怎么填 |
|---|---|
| 名称（标题） | 事由，如"工资转存储""转1000到理财"；没给用"X→Y 金额" |
| 日期 | 默认今天；用户指定则 ISO `YYYY-MM-DD` |
| 来源账户 | 转出账户 relation；用户未指定且用户确认的默认账户未确认时询问 |
| 目标账户 | 根据用户明确说出的目标账户匹配；有多个候选时询问 |
| 转账金额 | 必填，单位元 |
| 转账路径 | 公式字段，Notion 自动算，**不填** |

**账户解析（转账场景）**：只在 Runtime 解析出的用户账户库中按用户提到的名称搜索。用户只说一个账户且来源/目标无法判定时，询问“从哪个账户转到哪个账户？”。

转账不属于收入或支出。仅当实时 Schema 表明转账库没有分类或报表关系时，才跳过这些字段；不根据其他用户的数据库结构作假设。

### 订阅场景（支出的一个分支）

触发词：`充/开通/续费/订阅 XX/XX会员/月费/年费/季付/买断`。把订阅费用作为支出；只有目标库实时 Schema 存在对应 relation/周期字段时才填写。

在用户自己的 `subscription` Data Source 中按服务名精确查找。唯一匹配时可关联；多个候选时询问。没有记录时，仅当用户确认要建立订阅产品且目标库存在可写 title 字段，才用 `notion_create_pages` 新建最小记录。创建前按实时 Schema 调用 `check-write`，不复制已有订阅页面。

| 字段 | 怎么填 |
|---|---|
| 支出标题 | 用户说出的服务名 |
| 金额 | 必填 |
| 日期 | 订阅发生日，默认今天 |
| 账户 | 用户指定或已确认的默认账户 |
| 分类 | 匹配用户当前分类库中的订阅相关分类；不唯一时留空并说明 |
| 订阅关系 | 目标库及关系字段存在时，关联唯一匹配的订阅页面 |
| 周期 | 目标库有相应字段且用户说清时填写 |
| 备注 | 用户说了才填 |

可用时再按交易日期关联报表。

### 报销场景（发截图 → 读信息 → 落单 → 存图）

触发词：`报销/这笔要报销/帮我报销 XX`，或用户发来一张**报销截图/收据/账单**。报销 = 工作或项目产生的、需要报账的费用，写进「报销」库。

| 字段 | 怎么填 |
|---|---|
| 名称（标题） | 报销项目名，从截图或事由读（如"某项目材料"） |
| 金额 | 必填，从截图/用户话读（元） |
| 日期 | 报销发生日期（默认今天；从截图读到的日期优先；ISO 写入） |
| 付款账户 | relation → 账户库，用户指定或已确认的默认账户 |
| 分类 | select，从用户 Schema 的现有选项中选择；**匹配不到就留空并标注**，不造新分类 |
| 已报销？ | 若用户未说明且 schema 明确表达未报销状态，则使用该值；否则不填 |
| 进程 | 若 schema 有唯一且明确的初始选项时才填写，否则不填 |

**分类选项**：从本次解析到的用户报销库实时 Schema 中读取。只选择现有且含义明确的选项；没有匹配项时不造选项，留空并说明。

**流程**：
1. 用户发截图时，先读取截图并提取名称、金额、日期及可见的分类信息；不推断付款账户。
2. 根据实时 Schema 构造本次要写入的属性；账户未明确时先询问。
3. 使用 `notion_create_pages` 在 Runtime 解析出的报销 Data Source 直接新建记录，不复制任何既有记录。
4. 仅在当前用户库存在相应可写字段且附件工具支持时存图；否则保留报销记录并说明附件未写入。
5. 回读核验后报告结果；只在必要字段缺失时追问。

**附件处理**：遵循当前 Notion 工具支持的上传方式。先确认报销库的附件字段或正文可接收附件，再写入并回读核验；字段不存在或工具不支持时不要尝试不明格式，也不要宣称截图已保存。

**分类判断**：先看用户是否明确指定分类；否则根据事由含义，在 Runtime 已解析的用户分类库中找唯一且语义明确的现有分类。禁止照搬任何示例系统的分类名。找不到明确匹配时留空并标注；对含义不明的用户自定义分类，不要从名称猜。

### 不碰

- **日报/周报/月报/年报**：属于可选报表挂靠，按下方规则处理。
- **所属大类**：自动或由用户系统汇总，不主动填。
- **公式字段**：Notion 自动算，不填。

### 报表挂靠（可选，按交易日期）

只有当用户的交易库实际包含报表 relation，且 Runtime 找到了对应报表 Data Source 时才执行。根据交易日期分别解析 `daily_report`、`weekly_report`、`monthly_report`、`yearly_report`，按日期精确搜索匹配页面；不要假设四种报表都存在。找不到唯一页面时留空并告知用户，不从既有交易复制报表关系。

### 属性值模板

下列仅展示结构，不含任何账户或页面 ID。实际属性名和字段类型必须以当前用户 Schema 为准；relation 的值使用在用户自己的目标库中查到的页面 URL。

支出/收入：标题、日期（ISO `YYYY-MM-DD`）、金额、用户确认的账户、可选分类、可选备注。未提供的字段不写入。

转账：名称、日期、转账金额、来源账户、目标账户。来源与目标均需明确。

订阅支出：按支出处理，并在 Schema 支持时填入订阅 relation 与用户说出的周期。产品不存在时，只有在用户数据库 Schema 允许直接创建且所需字段明确时，才创建最小订阅页；否则先询问。

报销：名称、日期、金额、付款账户，以及当前 Schema 中确实存在的分类、已报销状态、进程字段；按用户数据库的现有 select/status 选项填写。

## 执行流程

1. 判断本次场景：支出、收入、转账、订阅支出或报销。
2. 用对应 concept key 解析目标 Data Source；按实时 Schema 确认 title、日期、金额、relation 与 select 字段。必需目标缺失或多候选未消歧时停止相关写入并询问。
3. 只查询当前动作需要的账户、分类、订阅产品和报表页面。对 relation 页面进行精确匹配；不唯一时询问。账户未确认时询问本笔使用哪个账户。
4. 调用 Runtime `check-write`，传入目标 Data Source ID 和本次全部字段与选项；只提交用户授权范围内的值。未提供的可选字段保持空白。
5. 使用当前 Notion connector 支持的 Data Source 创建方式新建记录，并将父级设为 Runtime 返回的目标 Data Source。不得复制既有记录。如果 connector 不支持此操作，停止并说明限制，不尝试其他目标或替代路径。
6. 若工具异步执行，等待成功后回读新页面，确认 parent、属性与 relation 均匹配目标。
7. 向用户报告场景、金额、事由、日期、分类和账户；明确标注未匹配字段。

创建成功后不默认追问分类、备注或其他非必要信息；仅在缺失信息会影响正确归类或账户归属时询问。

## 旅行支出关联（可选）

仅当用户明确说这笔支出属于旅行，或当前对话足以确定时，使用 Runtime 的 `travel` concept 查找对应旅行。不得扫描用户全部旅行记录。唯一匹配时，且双方实时 Schema 都有对应 relation，才在本次用户请求涵盖此联动时更新；多个候选时询问，找不到则只记录支出。更新前重新读取目标页面并校验字段。

## 执行提醒

- 账户未确认时先问；分类找不到明确匹配时留空并标注。
- 支持用户一句话中多笔交易；每条交易分别按场景解析、校验并创建。
- 若 Notion 工具异步执行，等待任务成功后再回读。
- 页面未落入目标 Data Source 时停止，说明工具限制，避免重复写入。
