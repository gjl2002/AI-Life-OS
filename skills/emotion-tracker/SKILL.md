本 Skill 使用 `$ai-life-system-init` 定位用户自己的 Notion 结构。执行前先运行 `scripts/runtime.py status`；状态为 `needs_init` 时先引导用户完成初始化。对本次操作涉及的每个概念运行 `scripts/runtime.py resolve --concept <key>`，只使用 Runtime 返回的目标 Data Source ID。读取该 Data Source 的实时 Schema，并在写入前运行 `scripts/runtime.py check-write` 校验本次属性、选项和 relation。

创建时必须让当前 Notion connector 将新页面的 parent 指向已解析的 Data Source；写入后回读确认 parent 和属性。若概念未找到、结构不兼容、候选不唯一或 connector 无法确认 parent，应停止该写入并说明原因，不得猜 ID、扫描无关空间或复制已有个人记录。以下正文中的数据库路径、字段名、选项和默认值若与用户实时 Schema 不一致，均视为示例而非要求；只有语义和字段类型明确匹配时才映射，否则询问或安全停止。仅读取本次任务所需的数据；不得将用户本地索引、凭据、页面 ID 或个人样例打包发布。

# Emotion Tracker — Notion 情绪记录

## 数据库

- **目标数据源**：以 Runtime 对 `emotion_log` 的解析结果为准

## 执行流程（照此执行）

### 1. 直接新建记录



### 2. 推断字段

从用户话里提取：发生了什么、情绪感受、时间。推断情绪类型、愉悦度、核心需求、我在想什么、我做了什么、下次建议。

### 3. 一次性 update 属性

```json
{
  "情绪": "M月D日 简短描述",
  "date:记录日期:start": "YYYY-MM-DDTHH:mm:00+08:00",
  "date:记录日期:is_datetime": 1,
  "情绪类型": "😰 焦虑",
  "愉悦度": "😕 有点不愉快",
  "发生了什么": "...",
  "我在想什么": "...",
  "核心需求": "🎯 掌控感",
  "我做了什么": "🆘 寻求支持",
  "下次遇到可以": "...",
  "时间段": null,
  "任务": null,
  "书籍": null,
  "课程": null,
  "信息": null,
  "内容": null,
  "笔记": null,
  "角色数据": null,
  "计时": null
}
```

**关键规则：**
- **记录日期必须是 datetime（is_datetime=1），带具体时间**。Notion 自动化会根据小时自动算时间段（0-3深夜/6-8早晨/10-12近午/12-14中午/14-16午后/16-18下午/18-20傍晚/20-22晚上）。如果设成纯日期（is_datetime=0），时间默认午夜，时间段会错误显示"深夜"。
- **时间段不要手动填**，置 null 让自动化算。
新页面只写本次记录明确提供的值；未提供的可选字段留空，不沿用其他记录的属性或正文。

### 4. 关联今日每日记录和本周复盘

- update 属性：`"每日记录": ["<当日页面URL>"]`、`"每周复盘": ["<本周页面URL>"]`

### 5. 验证

fetch 新记录，确认：parent-data-source = 情绪记录、时间段被自动化填上了正确值、每日记录和每周复盘已关联。向用户报告。

## 情绪类型选项

😄快乐 😆兴奋 ❤️感激 💪自豪 😌满足 🍃放松 🤔好奇 🥹感动 😡生气 😰焦虑 😤烦躁 😬紧张 🤢厌恶 😣委屈 😒嫉妒 😢悲伤 😞沮丧 😨害怕 😳羞愧 🫠内疚 😔失望 🧊孤独 🥱无聊 😲惊讶 😶迷茫

## 不碰

- 公式字段（心情、心情评分、相关事件、经验、跃点、金币、颜色、播报提醒）
- 时间段（自动化算）
- 用户没提到的 relation

## 注意

- 用户随口吐槽时先共情，再问"要记下来吗"
- 情绪强烈时优先回应人
