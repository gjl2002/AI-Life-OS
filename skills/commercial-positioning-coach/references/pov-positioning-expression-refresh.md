# POV, Positioning, Expression, And Refresh

Use this reference when positioning a product, service, personal brand, AI direction, or offer. Its purpose is to prevent generic tool labels and turn positioning into evidence-backed choices that remain revisable.

## Keep Four Layers Separate

| Layer | Core question | Typical stability | Evidence needed |
| --- | --- | --- | --- |
| POV / 定位母题 | What do we believe about this problem or category? | Relatively stable | Lived experience, repeated choices, customer insight, product decisions |
| Positioning | Why should this specific audience choose this offer now? | Revisable | Customer problem, current alternative, desire, method, relevant difference |
| Expression | How do those choices become recognizable? | Consistent but evolving | Language, product defaults, content, offer, delivery, explicit refusals |
| Proof | Does the market actually respond? | Continuously updated | Cases, behavior, conversion, retention, content, sales, competitor evidence |

Never use POV as proof of demand. Never use brand expression as proof of product value.

## 1. Derive A Real POV

A useful POV is a consequential belief, not a generic value such as `human`, `trustworthy`, `growth`, or `AI empowerment`.

Ask 1-3 questions at a time:

- What do you believe about this problem that shapes how you build or deliver differently?
- Which lived experience, customer observation, or repeated decision produced that belief?
- What would you refuse to do even if competitors commonly do it?

A real POV should imply choices. If it cannot change the product, offer, content, delivery, or audience, keep it as a hypothesis or discard it.

Do not manufacture controversy. `Polarizing` means accepting a tradeoff and being unsuitable for some people, not attacking a person or inventing an enemy.

## 2. Name The Current Alternative

Start with what the customer does today:

- manual workflow
- old software or static template
- outsourced labor or generic service
- fragmented tools
- direct competitor
- delay, avoidance, or doing nothing

Clarify:

```markdown
target_user:
current_alternative:
why_they_use_it:
where_it_breaks:
switching_trigger:
direct_competitor_difference:
evidence:
confidence:
```

The primary enemy is usually a broken behavior, assumption, or workflow. Use a named competitor only when the customer's real choice requires that comparison.

## 3. Build Positioning Clarity

Use this matrix before polishing wording:

```markdown
specific_audience:
recurring_problem:
desired_result:
current_alternative:
why_now:
specific_method:
relevant_difference:
reason_to_believe:
not_for:
```

Run two tests:

- `Cold-audience clarity`: can the intended user recognize themselves, the problem, and the result within ten seconds?
- `Optimal distinctiveness`: is the difference as strong as possible while the category and value remain recognizable?

Novelty without relevance is decoration. Clarity without a meaningful difference creates interchangeability.

## 4. Convert Positioning Into Choices

Create a lightweight expression contract:

```markdown
repeatable_core_language:
brand_or_personality_traits:
phrases_and_jargon_to_avoid:
product_defaults:
delivery_rituals:
proof_style:
content_or_story_patterns:
explicit_refusals:
hard_to_copy_assets_or_choices:
```

Prioritize choices that affect the product, service, or customer experience. Visual identity is optional and downstream.

Run these checks when relevant:

- Put the homepage/offer headline, one recent content item, and one delivery touchpoint together. Do they reinforce the same positioning?
- Replace the user's name or logo with a direct alternative. Would the message and choices still fit too easily?
- Are the differences visible in behavior and delivery, or only claimed in adjectives?

## 5. Give AI A Sharp Input Contract

AI can expand a positioning system but should not invent the user's belief or market proof. Before generating copy, content, or offers, provide:

- confirmed POV and its evidence
- specific audience, problem, desired result, and current alternative
- method and reason to believe
- repeatable language and real examples
- forbidden generic phrases and unsupported claims
- explicit refusals and non-fit users
- confidence labels and missing evidence

If these inputs are thin, generate questions or hypotheses instead of confident brand language.

## 6. Refresh Without Losing The Core

Separate the stable and dynamic layers:

- Usually stable: worldview, ethical boundary, durable problem insight.
- Revisable: target segment, problem framing, current alternative, method emphasis, offer, language.
- Fast-changing: features, channels, campaigns, model or tool claims.

Trigger a positioning review when:

- a new competitor or category frame changes how customers compare options
- a new model, platform, or mechanism changes the user's workflow
- customers repeatedly misunderstand who the offer is for or why it matters
- content attention, conversion, retention, or referrals plateau for a meaningful period
- actual customer value differs from the original promise
- delivery or product behavior changes enough that the old positioning is no longer true

Record:

```markdown
positioning_version:
review_date:
stable_pov:
changed_assumption:
new_evidence:
positioning_change:
next_validation:
```

Do not change positioning merely because a new phrase sounds fresher. Require a changed comparison, customer insight, market signal, or product truth.

## AI And New-Element Guardrail

`AI-powered`, `AI + X`, and `Notion + AI` describe a mechanism or ingredient, not a complete positioning.

Use `new-element-species-positioning.md` to judge whether AI changes multiple dimensions such as the first user, problem, method loop, product form, commercial relationship, or growth loop. If it only makes an old workflow faster, keep the original category and position around the user value rather than the tool.
