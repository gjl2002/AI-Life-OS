## 用户自己的 Notion 接入

本 Skill 使用 `$ai-life-system-init` 定位用户自己的 Notion 结构。执行前先运行 `scripts/runtime.py status`；状态为 `needs_init` 时先引导用户完成初始化。对本次操作涉及的每个概念运行 `scripts/runtime.py resolve --concept <key>`，只使用 Runtime 返回的目标 Data Source ID。读取该 Data Source 的实时 Schema，并在写入前运行 `scripts/runtime.py check-write` 校验本次属性、选项和 relation。

概念映射：`task, project`。

创建时必须让当前 Notion connector 将新页面的 parent 指向已解析的 Data Source；写入后回读确认 parent 和属性。若概念未找到、结构不兼容、候选不唯一或 connector 无法确认 parent，应停止该写入并说明原因，不得猜 ID、扫描无关空间或复制已有个人记录。以下正文中的数据库路径、字段名、选项和默认值若与用户实时 Schema 不一致，均视为示例而非要求；只有语义和字段类型明确匹配时才映射，否则询问或安全停止。仅读取本次任务所需的数据；不得将用户本地索引、凭据、页面 ID 或个人样例打包发布。

# Task Tracker — Notion 任务录入

## 数据库


## 输入

用户自然语言说一件要做的事，可能是：
- "晚上8点取快递"
- "明天下午3点面试"
- "记得交材料"
- 发来求职测评/面试截图

## 执行流程

### 1. 直接新建记录

在 Runtime 已解析的用户 Data Source 中直接创建新记录；不复制现有记录。


### 2. 解析任务信息

从用户话里提取：

| 字段 | 怎么提取 |
|---|---|
| **任务名** | 用户说的具体事情 |
| **任务日期** | 有具体日期时间就带时间（is_datetime=1）；只有日期就 is_datetime=0；没说日期就留空 |
| **是否待办** | 琐碎小事（取快递、交材料、突然想到的事）→ 是；正在推进的正经事 → 否 |
| **是否求职** | 提到面试/测评/笔试/公司招聘/求职 → 是 |

### 3. 判断情景标签

**普通任务：**
- 琐碎待办 → `["☑️ 待办"]`
- 正经事 → 情景留空（用户自己按场景加电脑/手机/学校等）

**求职任务（从截图或描述判断）：**
- 测评/AI面试/笔试 → `["⭕ 测评"]`
- 真人面试 → `["✌️ 面试"]`
- 如果是琐碎的求职小事（如"发简历"），同时加 `"☑️ 待办"`

### 4. 判断项目关联

- **普通任务** → `项目` 置 null

### 5. 一次性 update 属性

```json
{
  "任务": "<任务名>",
  "date:任务日期:start": "<YYYY-MM-DDTHH:mm:00 或 YYYY-MM-DD>",
  "date:任务日期:is_datetime": 1 或 0,
  "情景": ["<情景标签>"],
  "项目": ["<项目URL>"] 或 null,
  "状态": "<按下方规则选择>"
}
```

新页面只写本次记录明确提供的值；未提供的可选字段留空，不沿用其他记录的属性或正文。
- 有具体日期时间的任务（面试、约会、提醒）→ `"未来"`
- 没说日期的琐碎待办（取快递、想到就做）→ `"收集"`
- ⚠️ **绝对不能是"完成"**——既有页面如果是已完成的任务，状态会带过来，必须覆盖

**日期格式规则：**
- 有具体时间（如"晚上8点"）→ `start` = `2026-09-24T20:00:00`，`is_datetime` = 1
- 只有日期（如"明天"）→ `start` = `2026-09-25`，`is_datetime` = 0
- 没说日期 → 日期相关字段全部 null

新页面只写本次记录明确提供的值；未提供的可选字段留空，不沿用其他记录的属性或正文。
- `每日复盘` → null
- `计时` → null
- `情绪` → null
- `角色数据` → null
- `积分设定` → null
- `专注总时长(min)` → null
- `专注状态` → null

### 6. 验证

`notion_fetch` 新记录，确认：
- parent-data-source = 任务
- 任务名、日期、情景落库
- 求职任务已关联求职项目
- 旧 relation 已清理
- **⚠️ 状态不是"完成"**——如果是，立即 update 改成"未来"或"收集"

向用户报告。

## 截图处理（求职）

当用户发来截图时：
1. 用 Read 读取截图，提取公司名、面试/测评时间、方式（线上/线下）、链接
2. 任务名格式：`<公司名> <面试/测评>`，如"字节跳动 一面"
3. 如果截图里有具体时间，填入任务日期（is_datetime=1）
4. 情景按规则选"✌️ 面试"或"⭕ 测评"
5. 关联求职项目

## 不碰

- **状态**：按规则显式设置（有日期→未来，无日期→收集），绝不能继承成"完成"
- **优先级**：不自动设
- **公式字段**（提醒、经验、金币、跃点、血量、游戏化概览等）：Notion 自动算
- **按钮字段**（专注、休息、等）：用户自己点
- **完成日期**：完成时自动填

## 边界

- 用户没说日期 → 日期留空，状态"收集"
- 判断不准是不是求职 → 问一下用户
- 截图信息不全（没公司名/没时间）→ 提取能提取的，缺的问用户
