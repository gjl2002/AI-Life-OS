# 每日晨报

把今日安排放回本周战术和当前周期，交付一页能读完并马上行动的晨报。使用 [晨报模板](assets/morning-template.md) 和 [Notion 读取与写回](references/notion-runtime.md)。

## 运行模式

- 用户说「今天该先做什么」「生成晨报」或要求预览时，在对话里交付。
- 用户明确要求保存到 Notion，或已配置的定时任务明确授权写入时，按写回流程保存。当次调用从其已确认的配置中读取业务日期、时区和目标。
- 业务日期优先用调用方明确指定的日期。否则取用户已确认的时区下的当天，或宿主可确认的运行时区。日期、星期和周界线统一使用同一口径。

## 读取与判断

1. 使用 `ai-life-system-init` Runtime 解析各个数据源，按 [读取清单](references/notion-runtime.md#读取清单) 对当天、昨天、本周和当前周期做有限查询。没有可用连接时，可依据用户当前提供的材料交付预览，并注明缺口。
2. 从当前周期读取实际目标，沿任务、项目和目标的已核实关系标注对应战术。当前周分数取对应周复盘的执行评分，写明周区间。只有周期平均执行率时按周期指标呈现。状态缺失、空结果和已确认的零值分别标明。
3. 独立查询「信息」「书籍」「课程」三个学习库的实际在学状态。每库都报告已读条目与进度、零条，或缺失原因。只有实际完成节数、总节数等字段支持时才计算进度。
4. 有进行中的周期且能读取用户已授权的近 14 天情绪记录时，结合用户自述、周期进度、周表现和实际阻碍，可给一个暂定的执行体验阶段及置信度。信号不足时写「证据不足」。没有进行中的周期时写「阶段不适用」。情绪记录属于可选证据。
5. 阅读已安装 `12-week-work-coach` 的周计划方法（`references/weekly-routine.md`），只取从本周战术筛选今日行动的步骤。当前平台无法加载该 Skill 时，按下面的排序原则完成晨报。用户要重做完整周期计划、执行诊断或回顾时，可另行调用该教练。
6. 先看今日确实到期的任务，再看会阻塞别人或本周交付的逾期任务，接着看直接推进周期目标的周行动。按真实容量选择一个核心任务及最多两个支线，写清可核验的完成标准。任务证据不足时用一条需要先确认的事项收尾。

列出影响今天决定的昨天进展、当前目标与项目、任务紧迫度和学习进度。可按用户需求附一句可核实来源的提醒；缺少可靠出处时省略引语。

## 写回

写入用户确认的共享「日报」数据源，使用完整标题 `YYYY-MM-DD 晨报`、`标签 = 晨报` 和当天唯一的「每日记录」关联。标题加标签查重，唯一匹配时局部更新，无匹配且无冲突时创建，多条或同标题异标签冲突时停在预览。执行前读取实时 Schema 并运行写入预检，执行后回读核实父数据源、标题、标签、当天关联和完整正文。详见 [写回步骤](references/notion-runtime.md#写回步骤)。
