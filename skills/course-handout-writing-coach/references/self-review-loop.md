# Self-review Loop / 自审—修订闭环

Use this loop for substantial full lessons, full-course production, high-stakes release, or when the user asks for rigorous review. Ordinary bounded handout edits use the eight core gates in `SKILL.md` and do not require a visible audit report.

## Loop

```text
Draft 1
→ reviewer pass (four lenses)
→ findings report
→ targeted repair
→ re-check of failed items
→ release report or explicit remaining gaps
```

## Four Review Lenses

| Lens | Reviewer question | Typical failure |
| --- | --- | --- |
| Skeptical learner | Do I understand why my old move fails, what I do next, and how I know it worked? | abstract judgment, hidden steps, dead assignment |
| Evidence editor | Can every consequential claim be traced to an appropriate source type and wording? | invented proof, personal case inflated into a law, floating theory |
| Instructor | Can this be delivered in the requested format and duration? If screen, demo, or contingency is promised, does it work? | article-like script, fake duration, requested deck duplicates speech |
| Course architect | Does this own a distinct role, consume the previous asset, and create the next one? | duplicated lesson, broken handoff, concept introduced too early |

## Findings Report

Create this report after Draft 1 and before Revision 2:

| Severity | Finding | Evidence / location | Why it matters | Exact repair | Re-check result |
| --- | --- | --- | --- | --- | --- |

Severity rules:

- **Blocker**: false or unsupported core claim; missing learner deliverable; broken course handoff; duration cannot plausibly meet promise; source/IP breach. Do not release.
- **Major**: causal explanation lacks proof/boundary; a core segment is shallow; demo/PPT/script conflict; essential user-language or case gap. Repair before `已完成`, or state it prominently as a known gap.
- **Polish**: wording, pacing, visual refinement, optional supplementary example. May remain only when it does not block teaching.

## Re-check Rules

- Re-check only the claims, sections, pages, or timing rows that were changed, plus their direct dependencies.
- A repair is not valid merely because it added words; it must resolve the finding's causal, evidence, delivery, or continuity problem.
- Record remaining gaps in the 取材账本 / release note. Never silently convert a gap into certainty.

## Release Report

Before handoff or Notion writeback, state internally:

```text
review status: pass / pass with named gaps / blocked
blockers: 0
major issues resolved: list
remaining gaps: list or none
duration status: estimated / rehearsal-verified
```
