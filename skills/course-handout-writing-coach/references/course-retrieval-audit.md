# Course-level Retrieval Audit / 课程取材审计

Use this audit for full-course production, evidence-sensitive lessons, or when the user asks for an auditable retrieval record. An ordinary handout does not require a course-level audit.

`完整检索` means every important teaching job has been routed to a relevant Runtime source or marked as a visible gap. It does not mean reading every database or every relation.

## Audit Sequence

1. Obtain the current `$ai-life-system-init` Runtime and resolve the course/product sources needed by the current scope.
2. For each lesson claim card, identify five roles: external mechanism, user's own judgment, real practice, user language, executable asset.
3. Route each missing role to the smallest relevant concept or user-named source.
4. Log query terms, result status, selected pages, exclusions, and gaps.
5. Read selected records fully enough to extract mechanism, example, boundary, and usable detail.

## Runtime Routing Examples

- Course contract and current lesson: `course`, `product`, or a user-named page.
- Audience and real language: `user_profile`, `user_feedback`, `content`, or the current customer source.
- Knowledge and mechanisms: `note`, `information`, `question`, `book`, or a user-named course/source.
- Executable assets: `sop`; for Agent assets, resolve the real source name `Agent` if the stable concept is unavailable.
- Practice evidence: only the relevant `project`, `goal`, review, case, or user-provided record.

Add a source only when it serves a concrete claim, scene, method, example, asset, boundary, or feedback rule.

## Completion Rule

The audit is complete only when each major teaching claim has either a selected source and evidence role, or a visible gap and cautious wording. It is never complete merely because many folders were listed.
