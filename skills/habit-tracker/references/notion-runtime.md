# 数据源与字段

## 定位数据源

从 `ai-life-system-init` 目录运行 `python3 scripts/runtime.py status`。找不到索引时先完成初始化，索引有缺口时检查所需源的读取状态和绑定情况。以下名称用于匹配，对每项操作使用当前用户索引和实时 Schema 确认真实位置。

| 用途 | 起点 | 核对依据 |
| --- | --- | --- |
| 习惯定义 | `resolve --concept habit` 或 `resolve --source 习惯` | 习惯名称 title、状态等定义字段 |
| 打卡记录 | `resolve --source 打卡` | 打卡标题、日期、习惯 relation，relation 指向已确认的习惯定义源 |
| 每日记录 | `resolve --concept daily_record` 或 `resolve --source 每日记录` | 日期字段和打卡源的每日复盘 relation 指向同一数据源 |

习惯定义与打卡记录可同属一个数据库容器。操作目标是独立的 Data Source。返回多个候选时，用真实数据源标题、字段类型和关联目标缩小范围。若用户使用不同命名，可根据用户指定的链接确认后再按真实源名解析。多个候选仍无法区分时请用户确认，并明确哪些操作能继续。

## 映射字段与预检

| 语义 | 常见字段 | 写入说明 |
| --- | --- | --- |
| 打卡标题 | 打卡记录 | 实际 title，格式为习惯名和当日序号 |
| 打卡日期 | 日期 | 纯日期用 `YYYY-MM-DD`。日期时间带实际时区偏移 |
| 已完成标记 | 是否打卡 | 用当前 Schema 核对对应选项，例如「已打卡」 |
| 习惯关联 | 习惯 | 确认关联目标和页面归属，再用连接器支持的页面 ID 格式传入 |
| 每日记录关联 | 每日复盘 | 按每日记录真实的业务日期字段查找，与打卡日期一致且唯一时填写 |
| 习惯定义 | 习惯、状态、类型、目标次数、打卡周期、开始日期、打卡标记 | 只在明确新建或修改定义时写入对应字段 |

写入前，对实际父 Data Source 运行 `check-write --data-source-id <真实ID> --operation create|update`，逐项传入真实 `--field` 和适用的 `--option`。仅在预检通过、实时 Schema 与索引匹配、页面归属已确认且本次操作获得授权时写入。积分、角色和自动汇总由模板处理。公式、rollup 和按钮不作为写入字段。只收到公式引用时，用能核验的记录数据统计。

若每日记录暂未生成、找不到可用关联字段或无法唯一匹配，可在打卡必填字段满足时先记打卡并说明关联状态。若数据库要求该关联才能创建，先解决字段或归属问题。每天的记录由原流程生成。

## 查询与回读

- 使用当前 Notion 连接器支持的数据源查询及筛选。需要 SQL 时，参数化输入，查询真实索引返回的源和字段，并按连接器表示解析 relation，精确比较规范化页面 ID。使用具有相同筛选条件的全部分页或已确认完整的计数结果。
- 日期时间按实际本地日历计算区间，查询时可用本地开始日零点和结束日次日零点转换出的时刻作为半开区间。仅日期的值直接按日历日比较。避免按 UTC 日期分组，也避免把固定 UTC 偏移套给其他时区。
- 创建或更新后用返回的页面 ID 回读并比对真实父 Data Source 与属性。回执同时标明缺失或待确认的关联。
