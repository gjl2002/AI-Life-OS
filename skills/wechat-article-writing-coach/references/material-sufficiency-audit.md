# Material Sufficiency Audit and Retrieval Loop

Run this audit immediately after `context-verification-pass.md` and before the article battle card. It is a drafting gate, not a final polish checklist.

The purpose is to stop a familiar failure: the draft sounds fluent but its core judgment has no mechanism, no real scene, no traceable support, or no distinct contribution. Do not compensate for a missing source with generic explanation.

Passing this audit means the pool contains enough material. It does not mean every selected source belongs in the body. After this audit, run `editorial-claim-audit.md` to separate direct support from material that is merely adjacent to the topic.

## Audit Record

Create this compact working record:

```markdown
材料充分性审查：通过 / 条件通过 / 不通过

| Hard row | Status: pass / weak / missing | Selected material or claim | Exact gap | Retrieval route | Completion condition |
| --- | --- | --- | --- | --- | --- |
| Core judgment |  |  |  | topic / user input |  |
| Reader recognition |  |  |  | user feedback / avatar / existing content |  |
| Personal scene or owned observation |  |  |  | personal-path sources |  |
| Mechanism or conceptual support |  |  |  | books -> deep articles -> original public sources |  |
| Public-claim traceability |  |  |  | original study / interview / book / report |  |
| Differentiation from published content |  |  |  | 创作大脑 / 内容 |  |
| Historical correction when triggered |  |  |  | closest related content -> comments/feedback -> later review |  |
| Concrete reader next move |  |  |  | user's actual workflow / project / scene |  |
```

## Passing Standard

- `Core judgment`, `reader recognition`, `differentiation`, and `concrete reader next move` must pass for every full article.
- `Personal scene or owned observation` must pass when a safe public scene exists or the user asked for one. If no usable public scene exists after personal-path retrieval, record that fact and do not invent; this can be a conditional pass with a final source warning.
- `Mechanism or conceptual support` must pass for method, learning, decision-making, creativity, agency, attention, habits, self-knowledge, life-direction, or other articles that explain why a practice should work. A personal essay or sharp opinion can pass with a clearly framed user observation instead of forced theory.
- `Public-claim traceability` must pass whenever the article uses a public fact, study, book, named speaker, interview, talk, or report. If the article makes no public claim, mark it not applicable.
- A `weak` hard row is not a pass. Do not use a source merely because it is vaguely related.
- `Historical correction when triggered` must pass when the topic previously received a factual/conceptual correction or the new draft updates a technical/product claim. Otherwise mark it not applicable.

`条件通过` is allowed only when the remaining gap is non-hard, the article wording has already been weakened to match the evidence, and the source warning will be disclosed if it affects truthfulness. Otherwise the audit is `不通过`.

## Targeted Retrieval Loop

When a row is weak or missing:

1. Name the exact missing item. Do not write `补一些理论` or `再找案例`; write, for example, `解释“及时展开灵感为何更容易转化为产出”的一个可核验机制`.
2. Use the row's retrieval route. Search the smallest relevant source set first; do not restart broad retrieval.
3. Add the selected material to the preflight pool and map its specific article role.
4. Re-run this audit, not just the edited row, because new evidence can change the article's scope or claim wording.
5. Use at most two focused retrieval rounds. If the gap remains, remove or weaken the claim. Ask the user only when the missing item is their own stance, scene, product fact, or sensitive/publicability decision that cannot be discovered safely.

Do not build the battle card or draft while any hard row is `weak` or `missing`.

## Routing Table

| Audit failure | Return to | What to retrieve |
| --- | --- | --- |
| Core judgment is vague | topic page, user input, existing draft | one falsifiable, reader-relevant sentence the article will defend |
| Reader pain is generic | user feedback, avatar, comments, related content | a concrete reader scene, wording, objection, or cost of inaction |
| No usable personal scene | personal-path sources | one truthful scene, observation, decision, or explicitly record `no usable public scene` |
| Mechanism is thin | user book notes first; then high-quality/deep articles; then original public sources | one focused explanation that explains the article's central causal step |
| Public evidence cannot be named | original study, interview, talk, book, or report | source identity, direct link, and the exact claim it supports |
| Article overlaps earlier work | `创作大脑 / 内容` | distinct question, new evidence, new consequence, counterexample, or explicit sequel angle |
| Earlier feedback may invalidate the claim | closest related content, comments/feedback, directly related later review | the original claim, verified correction, and wording boundary that should survive |
| Advice is abstract | real workflow, project notes, personal scene | one low-cost action the reader can actually take |

## Post-Draft Return Loop

Run this after reader-flow and AI-flavor review whenever a repair exposes a material gap:

| Symptom in draft | Return point |
| --- | --- |
| Theory is thin, or the draft only says `我觉得` | mechanism/conceptual-support retrieval |
| Story feels decorative or the opening has no lived entry | personal-scene retrieval and battle card |
| The argument duplicates an earlier article | published-content differentiation gate and angle selection |
| A public claim reads like `研究显示` with no source anchor | original-source retrieval and attribution record |
| The ending gives only a slogan or broad advice | concrete-reader-next-move retrieval |
| Wording is generic or AI-like but evidence is sufficient | rewrite from the user's voice/AI-flavor library; no new retrieval needed |

After returning, re-run the affected review gate and the final quality script. Do not use this loop to force theory into every article; use the lightest credible support that the article type actually needs.
