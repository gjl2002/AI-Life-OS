# Final-release Audit / 终稿审计

Do not call a substantive lesson final after a first draft or a named second draft. The goal is a release-ready final manuscript, reached through diagnosis-led revision until all applicable gates pass.

## Diagnose Before Rewriting

| Failure | Diagnostic question | Repair |
| --- | --- | --- |
| Shallow claim | Does it explain a cause or only state an opinion? | add causal chain and a boundary |
| Floating theory | Does the theory change a learner decision here? | integrate at mechanism node or remove from spoken text |
| Weak proof | Is the case real, bounded, and relevant? | replace with real practice/demo or mark hypothetical |
| Repeated concept | Has this already been explained deeply elsewhere? | reference and apply it instead of re-teaching |
| Time illusion | When duration is promised, does the budget include the required interaction and delivery modes? | rebalance; add a worked example or cut duplicate abstraction |
| PPT mismatch | When a deck is requested, does each slide have one job and does speech expand it? | redesign page role, not merely shorten text |
| Dead asset | Is the submission used later? | create an explicit next-lesson consumption step |

## Final-release Exit Criteria

- every major claim has evidence type and source role;
- every causal mechanism is teachable in ordinary language;
- every asset has an incoming/outgoing place in the course;
- any promised delivery budget is plausible;
- requested script, PPT, demo, and learner action artifacts form one arc;
- source ledger and retrieval gaps remain available for future revision.

## Stop Rule

Run up to three focused internal repair cycles. If the same blocker persists, identify the exact missing input or external validation needed and mark the lesson blocked for final release. Do not continue generating cosmetic rewrites.
