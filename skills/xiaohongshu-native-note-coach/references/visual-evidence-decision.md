# Visual Evidence Decision

## Default Rule

Images are evidence, not decoration. Decide what each image proves before writing.

For enhanced, strict, campaign, and claim-heavy notes, pair this with `visual-context-verification.md` before final output.

## Image Evidence Roles

| Image type | What it proves | Best use |
|---|---|---|
| Life scene photo | person, lifestyle, state, real presence | cover or opening scene |
| Work/process screenshot | method, workflow, operating system, execution | proof image or carousel body |
| Product/course/poster image | product exists, offer clarity, event info | middle or final conversion image |
| Customer feedback/chat screenshot | trust, result, service evidence | proof image, usually blurred |
| Milestone proof | progress, status, social proof | cover if visually strong, otherwise support |
| Third-party story image | story context, metaphor, public event | cover for story notes |
| Concept visual/diagram | method memory, structure | support image |
| QR code/contact card | conversion path | final image only |

If an image cannot prove the title/body claim, treat it as scene-setting or decoration. Do not write it as evidence.

## Cover Selection

Pick the cover image by this order:

1. strongest human/life presence
2. clearest result or proof
3. most visually legible workflow/product screenshot
4. strongest story emotion
5. conversion poster or QR code only when the note is explicitly sales-first

Avoid covers that:
- are visually cluttered
- reveal private data
- need long explanation to understand
- feel like a hard ad before trust is built

## Carousel Sequencing

Use this sequence when possible:

1. Cover: stop scrolling.
2. Context: show scene, state, or problem.
3. Proof: screenshot, feedback, product, milestone, process.
4. Method: diagram, checklist, or specific system.
5. Conversion: QR code, poster, or call-to-action image only if needed.

## Privacy And Safety

Recommend blurring:
- names, avatars, phone numbers, WeChat IDs, order IDs
- private client/company information
- unpublished product details
- sensitive financial screenshots
- private Notion URLs, database names, or internal product/template names

Do not invent image content. If the image is unclear, say what can be inferred and ask for context only if needed.

If a screenshot or image contains an unapproved internal project, template, workspace, client, contact, or account name, recommend cropping, blurring, covering, or omission unless the user explicitly approves public use.
