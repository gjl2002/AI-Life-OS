# Course Structure Rules

Use this reference when the product architecture includes a course, training camp, workshop, manual, or curriculum.

## Transformation Path

Start from:

```text
这门课帮助【某类人】从【问题状态】走到【目标状态】。
```

Break the path into:

- 起点: what the user is doing, feeling, or failing at now
- 拐点: what they must understand, decide, build, practice, or submit
- 终点: what they can own, do, or continue after the product

## Stage Design

Use 3-5 stages. Each stage should represent a real transformation point:

- cognitive shift
- decision shift
- behavior shift
- asset-building shift
- feedback/iteration shift

Avoid vague stage names:

- 基础认知
- 理论框架
- 工具介绍
- 高级进阶

Prefer result-oriented stage names:

- 识别当前最影响结果的卡点
- 完成第一版可用方案
- 用真实案例跑通关键步骤
- 根据反馈完成一次迭代

## Lesson Design

Each lesson should solve one user question:

- 我为什么卡在这里？
- 我该先做哪一步？
- 我怎么判断自己做对了？
- 我怎么把材料变成自己的系统？
- 我交付什么东西才算完成？

Each lesson should include:

- lesson title
- problem it solves
- method/SOP
- example or demonstration
- student task
- visible deliverable
- feedback or self-check rule

## Title Rules

Good course titles are:

- short
- concrete
- user-language based
- result-oriented
- not overloaded with jargon

Use titles that expose value:

- `明确第一批用户的问题`
- `完成一份可交付方案`
- `用反馈修正产品`

Avoid titles that only name knowledge:

- `目标管理基础`
- `工具模块介绍`
- `方法框架理论`

## Training Camp Additions

If the product is a training camp, add:

- cohort rhythm
- assignment schedule
- check-in rule
- feedback format
- peer visibility rule
- graduation artifact
- provider workload boundary

Do not call a product a training camp if there is no assignment, cadence, or feedback loop.
