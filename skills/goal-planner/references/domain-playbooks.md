# Domain Playbooks

Use this reference when a goal belongs to a specific domain where generic planning may create shallow or misleading advice.

Label these as `领域常识`, not as Notion/system evidence.

## 1. Health / Fitness / Fat Loss / Muscle Gain

Use for goals like:

- 减脂增肌
- 减肥
- 体态改善
- 运动习惯
- 睡眠和精力改善

Evidence to check:

- current baseline: weight, waist, body photos, body fat if available
- current habits: workout, sleep, diet, screen/impulse habits
- execution records: 打卡, 专注, 每日复盘
- historical high/low events: 人生时刻 when health changed significantly

Planning rules:

- Do not set precise weight/fat-loss target from stale baseline.
- First establish baseline if current body data is missing.
- Separate training habit from setup projects.
- Diet rules should be low-friction unless the user already tracks food.
- Sleep/recovery is a risk factor, not a decorative note.

Project examples:

- 建立身体数据基线
- 设计低负担饮食规则
- 搭建训练记录与每周复盘模板

Habit examples:

- 每周 3-4 次训练
- 每周固定记录体重/腰围
- 每天 2 餐蛋白质优先
- 睡前降低刺激输入

Common mistakes:

- treating "work out 30 times" as a project instead of a habit/result
- setting a target weight without current baseline
- ignoring diet while only adding exercise
- making the system too complex in week 1

## 2. Research / Thesis / Graduate Work

Use for goals like:

- 完成论文初稿
- 跑通实验
- 完成文献综述
- 组会汇报
- 毕业推进

Evidence to check:

- current research project/pages
- tasks and project status
- recent focus records
- review notes about blockers
- deadlines from school/lab if available

Planning rules:

- Define the deliverable: draft section, figure, experiment result, dataset, presentation, submission.
- Separate exploration from production.
- Use weekly artifacts, not vague "科研进展".
- Identify dependency risks: equipment, advisor feedback, data quality, literature gaps.

Project examples:

- 完成实验结果图表第一版
- 写完论文方法部分初稿
- 整理 30 篇核心文献矩阵
- 完成一次组会汇报材料

Habit examples:

- 每周 4 次深度科研专注
- 每日记录实验/写作推进
- 每周一次论文结构复盘

Common mistakes:

- using "好好科研" as a goal
- planning too many parallel research threads
- ignoring advisor/lab dependency
- confusing reading more papers with producing output

## 3. Content Creation / Personal Brand

Use for goals like:

- 自媒体增长
- 发布文章/视频
- 账号定位验证
- 内容产品雏形

Evidence to check:

- existing content records
- content performance if available
- commercial positioning/project memory if the goal is monetization-oriented
- review notes about creation blockers

Planning rules:

- Separate positioning, production, distribution, and feedback.
- Use content experiments, not only output quantity.
- Define target audience and problem if known.
- Avoid overbuilding systems before publishing.

Project examples:

- 设计 3 个内容栏目
- 发布 6 篇定位验证内容
- 完成一次读者访谈与反馈整理
- 搭建选题库第一版

Habit examples:

- 每周发布 2 次
- 每日记录 3 个选题
- 每周复盘内容反馈

Common mistakes:

- only chasing output count
- no audience/problem hypothesis
- building templates instead of publishing
- confusing inspiration collection with content production

## 4. Learning / Exam / Skill Building

Use for goals like:

- 六级
- 英语听力
- 编程学习
- AI 工具学习
- 课程学习

Evidence to check:

- current level/baseline score
- course/project pages
- tasks and habits
- focus records
- recent review blockers

Planning rules:

- Establish baseline first: test score, diagnostic task, current ability sample.
- Split by modules: input, practice, feedback, review.
- Use deliberate practice, not passive watching.
- Build review loops for mistakes.

Project examples:

- 完成一次六级诊断测试
- 建立错题/错因系统
- 完成课程第一模块并做作品
- 做出一个可展示的小项目

Habit examples:

- 每日 30 分钟听力训练
- 每周一次错题复盘
- 每周两次输出练习

Common mistakes:

- watching courses without output
- no baseline
- no review of mistakes
- spreading across too many materials

## 5. Business / Monetization / Productized Service

Use for goals like:

- 商业化
- 产品设计
- 咨询服务
- 私域转化
- 模板/课程/MVP

Evidence to check:

- commercial positioning memory if available
- current products/services
- content and audience feedback
- sales/revenue records if available
- project/review notes

Planning rules:

- Define customer, problem, offer, proof, and channel.
- Validate before overbuilding.
- Keep first offer small and testable.
- Separate asset creation from market contact.

Project examples:

- 设计一个 99 元诊断服务
- 完成 5 次用户访谈
- 发布一页服务说明
- 整理 3 个案例证明

Habit examples:

- 每周联系 5 个潜在用户
- 每周发布 2 条问题洞察内容
- 每周复盘转化反馈

Common mistakes:

- building a full product before validation
- vague target user
- only polishing copy, not talking to users
- no proof or case evidence

## 6. General Domain Fallback

If the domain is not covered:

1. Identify the output type: artifact, behavior, metric, relationship, decision, or system.
2. Find baseline or mark it missing.
3. Define 2-4 projects only if they create deliverables.
4. Define habits only if repeated behavior is required.
5. Give first-week actions.
6. Label domain advice as `规划假设` if the domain knowledge is weak.
