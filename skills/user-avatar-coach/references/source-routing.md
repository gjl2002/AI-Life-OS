# 用户画像 Runtime 来源路由

## 总原则

云端 Notion 与用户本轮提供的材料是内容来源。`$ai-life-system-init` Runtime 只负责定位当前用户真实页面和 Data Source，不是用户证据。

每次先从 `$ai-life-system-init` 根目录运行：

```bash
python3 scripts/runtime.py status
python3 scripts/runtime.py resolve --concept user_profile
```

解析规则：

- `ready`：确认 `read_ready` 后实时读取云端；
- `multiple`：结合当前系统和业务对象消歧，仍不唯一才让用户确认；
- `not_found`：运行或引导用户运行 `$ai-life-system-init` 的 health-check / rebind；
- `needs_init`：先初始化，不退回固定 ID、本地数据库索引、全局模糊搜索或本地内容副本。

## 核心来源

| 研究作用 | Runtime 解析 | 读取条件 |
| --- | --- | --- |
| 已有画像与写回目标 | `--concept user_profile` | 正式研究、更新、查重或写回 |
| 商业方向约束 | `--concept commercial_positioning` | 结果需要商业解释或校准定位时 |
| 产品与交付背景 | `--concept product` | 产品专项或需要理解当前 Offer 时 |
| 客户事实 | `--concept client_management` | 需要确认客户身份、阶段或成交事实时 |
| 咨询、异议与沟通原话 | `--concept client_communication` | 研究购买、未购买、抗拒或需求表达时 |
| 使用与交付反馈 | `--concept user_feedback` | 研究实际价值、结果、满意与不满时 |
| 购买与收入信号 | `--concept income` | 购买证明或产品收入关系确实影响结论时 |
| 内容触发 | `--concept content` | 研究用户对内容与表达的真实反应时 |
| 账号背景 | `--concept account` | 研究平台受众或账号与画像关系时 |

需要竞品材料时，按需解析 `benchmark_account`、`benchmark_content` 或 `benchmark_product`，但只作为外部参考。概念不存在时，才按用户指定的真实 Data Source 或页面标题精确解析；不要因为概念未映射就断言资料不存在。

## 任务到最少来源

| 当前任务 | 优先读取 |
| --- | --- |
| 新画像 | 用户指定材料 + 用户画像 + 商业定位 |
| 更新已有画像 | 目标画像 + 新材料 + 必要商业定位 |
| 产品专项 | 用户画像 + 产品 + 客户沟通 / 用户反馈 |
| 购买与未购买 | 客户沟通 + 客户管理 + 必要收入记录 |
| 使用与交付 | 用户反馈 + 产品 + 必要客户事实 |
| 内容触发 | 内容 + 用户反馈 / 客户沟通 + 账号背景 |
| 批量分群 | 用户指定材料批次 + 相关已有画像 |
| 写回 | 用户画像实时 Schema + 重复候选 + 本次证据来源 |

先查看标题、描述、时间、摘要和 Relation，再选择真正可能改变画像判断的记录。不全库扫描，也不全 Relation 扫描。

## 证据优先级

同一结论冲突时，通常按以下顺序判断：

1. 用户本轮提供且身份清楚的近期访谈、私聊、咨询、未成交原因和交付反馈；
2. 云端近期客户沟通、用户反馈、客户行为、购买与交付记录；
3. 评论、问卷、内容互动和社群讨论；
4. 商业定位、产品说明、销售表达和既有画像；
5. 竞品、公开材料、行业信息和 AI 推断。

行为与购买记录通常比礼貌赞美更强，但不能凭行为擅自虚构动机。时间、产品和用户身份不一致时，要保留冲突而不是强行合并。

## 用户提供的材料

接受访谈稿、聊天文字、截图、录音转写、表格、问卷、评论、购买记录、未成交原因和交付反馈。截图文字不清时标记不确定，不把猜测文字作为关键原话。

如果用户指定 Notion URL、页面、记录或数据库，必须实时读取该命名来源。用户直接提供的材料不要求先进入 Notion 才能成为证据。

## 缺失来源

缺少客户、购买或使用证据时：

1. 明确哪些结论只能是假设；
2. 说明最值得补充的一类材料或一个访谈问题；
3. 指出什么信号支持假设，什么信号会推翻；
4. 不自动联网寻找陌生用户，也不用商业定位、理论或竞品材料补造真实用户。
