# 博主内容蒸馏器

## 一句话

给一份用户提供的小红书数据表，提炼可复用的选题与表达规律，并按用户确认的范围交付分析报告、测试结果和可选的创作 Skill。

## 数据使用边界

- 只处理用户在当前任务中提供或明确授权访问的数据；不擅自抓取私人账号、绕过访问限制或把数据上传到未授权的外部服务。
- 报告和生成的博主风格 Skill 可能包含原始笔记中的内容。默认只在当前对话或用户指定的位置交付，不自动发布、分享或安装。
- 生成可复用表达模式时提炼结构、选题逻辑和语言特征；避免复刻原帖句子或把博主个人经历改写成用户经历。

## 完整流程

```
Excel数据
  → 第1步：确认信息
  → 第2步：选题矩阵（分栏+子类+代表标题+标题公式）
  → 第3步：DNA提取（思维模型+选题公式+论证路径）
  → 第4步：爆文模型（≥5个模型+决策树）
  → 第5步：交付分析报告（Markdown；可选飞书）
  → 第6步：交互测试（你给模糊想法→生成标题+大纲+正文）
  → 第7步：生成博主风格Skill
  → 第8步：生成100个选题
```

## 第1步：接收数据并确认

### 1.1 读取Excel

```python
import pandas as pd
df = pd.read_excel(file_path)
# 确认列存在：笔记标题(列3)、笔记内容(列4)、点赞量(列5)、收藏量(列6)、评论量(列7)、分享量(列8)、笔记类型(列2)
```

**必须确认的列**：
- `df.iloc[:,2]` — 笔记类型（视频/图文）
- `df.iloc[:,3]` — 笔记标题
- `df.iloc[:,4]` — 笔记内容/正文
- `df.iloc[:,5]` — 点赞量
- `df.iloc[:,6]` — 收藏量
- `df.iloc[:,7]` — 评论量
- `df.iloc[:,8]` — 分享量

### 1.2 基本统计

```python
likes = df.iloc[:,5]
print(f'总笔记: {len(df)}, 均赞: {likes.mean():.0f}, 中位赞: {likes.median():.0f}')
print(f'万赞+: {(likes>=10000).sum()}, 千赞+: {(likes>=1000).sum()}')
```

### 1.3 向用户确认

展示基本统计后，问3个问题：
1. 这个博主叫什么名字？
2. 他是做什么的？（两三句话）
3. 你想从他身上学到什么？（可选）

## 第2步：选题矩阵

### 2.1 核心原则

- **不是机械分类**，是理解博主的"选题布局"
- **代表标题不是最高赞**，是最能体现子类特点的
- **"其他"类必须控制在全量10%以内**
- **每个子类必须给标题公式**

### 2.2 分类方法

编写 `classify_post(idx)` 函数，用标题+正文前500字进行正则匹配。分类规则必须**基于博主实际内容定制**，不能照搬模板。

**通用大类框架**（根据博主实际调整）：
- 方法论/教程类
- 产品/服务类
- 心态/情绪类
- 人设/身份类
- 信息差/内幕类
- 个人生活类
- 其他类（必须<10%）

**子类提取方法**：
1. 把所有标题按大类分组
2. 在每个大类内，读标题找选题角度的共性
3. 同一选题角度出现≥3次=一个子类
4. 子类命名要体现"这个选题在讲什么"，不是"内容形式"

### 2.3 代表标题选择标准

不是选最高赞的5个，是你读完这个子类所有标题后，挑出最能回答**"这个子类到底在做什么选题"**的标题。标准：
1. 选题角度典型——一看就知道属于这个子类
2. 标题手法清晰——能看出用了什么公式
3. 覆盖不同变体——不是同一句话换壳

每条代表标题必须配"为什么是代表"（一句话说清选了它的理由）。

### 2.4 标题公式提取

从子类的代表标题中，提取可复用的结构公式。

公式格式：`[元素A/元素B] + [元素C] + [元素D/元素E]`

- 方括号内是"可替换的语义槽"
- 斜杠表示同类选项
- 公式必须能从该子类≥3个标题中验证

### 2.5 输出格式

```
### 栏目X：[名称]（N篇，均赞XXX）

**栏目定位**: [一句话]

#### X.X 子类名称（N篇，均赞XXX）

**栏目定位**: [一句话说清选题特点]

**代表标题**:

| 点赞 | 标题 | 为什么是代表 |
|------|------|-------------|
| XXXX | XXX | XXX |

**标题公式**: `[A/B] + [C] + [D]`
```

### 2.6 校准

检查"其他"类占比。如超过10%：
1. 打印"其他"类中点赞最高的20条标题
2. 人工判断这些标题是否有共性
3. 如有共性，新建子类
4. 重复直到"其他"<10%

## 第3步：DNA提取

### 3.1 分析内容来源

首先读取点赞最高的15条笔记的**完整正文**（至少1500字的内容），理解博主：
- 正文是否只是话题标签？（视频博主的典型特征）
- 正文是否有实质性论证？（图文博主的特征）
- 正文的结构是什么？

### 3.2 提取思维模型

从标题+正文中提取3-5个核心思维模型。每个模型：

```
模型名称：[X]
公式：[伪代码表示]
使用场景：[什么时候用]
核心技法：[怎么落地]
```

**常见的思维模型类型**（从实际数据中提取，不是套模板）：
- 实证发现型：我做X年→发现Y→你们以为的Z是错的
- 反向焦虑解除型：你以为的问题是A→其实是更简单的B→不用担心
- UGC循环型：标题引发评论→评论成内容→再加工传播
- 内幕揭露型：有一个规则你不知道→没人告诉你→我现在说
- 产品力叙事型：我做了X→过程困难→困难让我做得更好

### 3.3 提取选题生成公式

还原博主的选题生产逻辑：

```
选题 = [变量1] + [变量2] + [变量3]
```

### 3.4 提取论证路径

分析正文的高频结构模式。如果是视频博主（正文只有话题标签），则分析标题的论证逻辑。提取3-5种结构模式。

## 第4步：爆文模型

### 4.1 选取范围

千赞以上笔记。如果千赞以上不足10个，扩大到500赞以上。

### 4.2 模型结构

每个模型必须包含6个要素：

```
模型N：[名称]

标题公式：`[公式]`

代表案例：
- XXXX赞： "标题"
- XXXX赞： "标题"  
- XXXX赞： "标题"

结构（≤4步）：
① [第一步]
② [第二步]
③ [第三步]
④ [第四步]

你能用：[什么场景适用]

操作步骤：
步骤1: [具体动作]
步骤2: [具体动作]
步骤3: [具体动作]
步骤4: [具体动作]
```

### 4.3 至少5个模型

覆盖博主最核心的爆文模式。第一个放最高赞的那个。

### 4.4 使用决策树

```
你的选题属于什么?                    → 推荐模型
"我有一个产品/服务"                   → 模型X + 模型Y
"我有一个群体想说的事"                → 模型X + 模型Y
"有信息/规律别人不知道"               → 模型X + 模型Y
"有一个时间节点要到了"                → 模型X + 模型Y
"有一个反常识的观点"                  → 模型X + 模型Y
"想引发讨论/互动"                    → 模型X + 模型Y
```

## 第5步：交付分析报告

### 5.1 组装报告

将第2-4步的内容组装为一个完整的Markdown文件，包含：

```
# 博主内容蒸馏分析报告

**博主**: XXX
**数据来源**: N篇小红书笔记
**分析日期**: 20XX年X月X日

## 一、选题矩阵（X大栏目 × N子类）
[完整的栏目+子类+代表标题+标题公式]

## 二、DNA提取
[思维模型+选题公式+论证路径]

## 三、爆文模型
[≥5个完整模型+使用决策树]

## 四、标题句式库
[从全部分析中提取12个已验证句式]

## 五、关键数据洞察
[视频vs图文、最高均赞子类、核心emoji等]
```

### 5.2 交付方式

默认把报告作为 Markdown 文件交付到当前工作区中用户可访问的位置。只有用户要求飞书交付，且当前环境已连接飞书并具备相应权限时，才调用当前可用的飞书集成创建文档。没有相应集成或权限时，保留 Markdown 文件并说明；不要假设特定操作系统、固定本地目录或命令行工具。

## 第6步：交互测试（验证DNA是否有效）

分析完成后，**主动邀请用户测试**。

### 6.1 问用户

"给我一个你模糊的选题想法，我用这个博主的DNA帮你生成"

### 6.2 生成内容

用户给出模糊想法后：

1. **匹配选题类型**——这个想法属于博主的哪个栏目/子类？
2. **套标题公式**——从该子类的公式库中生成3个标题选项
3. **套论证路径**——按博主的论证结构给出内容大纲
4. **指定爆文模型**——指出最适合用哪个模型

### 6.3 生成完整正文

如果用户对标题和大纲满意，直接生成完整的小红书正文（含话题标签）。

正文生成规则：
- 长度：300-800字（视博主风格而定）
- 结构：严格按博主的论证路径
- 语气：基于DNA提取的语言特征
- 产品插入：博主插产品的自然程度（软vs硬）

### 6.4 防抄袭检查

生成的内容必须通过自检：
- 标题：句式结构可以一样，但不能只是换产品名
- 正文：论证逻辑可以复用，但不能有连续10字以上和原帖相同
- 术语：可以用博主的标志词（如"邪修""含金量"），但不能连续套用整句

## 第7步：生成博主风格Skill

用户确认测试效果OK后，生成Skill文件。

### 7.1 Skill文件结构

```markdown
---
name: [博主名]-style
version: 1.0.0
description: "以[博主名]的选题逻辑和表达方式生成小红书笔记。输入模糊想法，输出标题+正文。"
---

# [博主名] 小红书内容生成器

## 你的身份

[2-3句话，基于DNA提取，定义这个博主的视角和说话方式]

## 选题矩阵速览

[简表：栏目、子类、标题公式、适用场景]

## 标题公式库

[从实际标题中归纳的12个句式，每个附博主原版标题示例]

## 论证路径

[博主的正文结构模板]

## 正文语法特征

[语气、高频词、句长、emoji使用规律]

## 防抄袭红线

[基于和博主原帖对比总结的避雷规则]

## 使用方式

用户输入：一个模糊想法、关键词、或选题方向
你输出：
1. 3个标题选项（从公式库中匹配）
2. 1个内容大纲（按博主论证路径）
3. 如果用户选择某个标题，输出完整正文+话题标签

## 示例

输入: "[一个模糊想法]"
输出: [展示标题+大纲+正文的完整链路]
```

### 7.2 保存位置

```
在当前 Codex Skills 目录中创建 `[博主名]-style/SKILL.md`，交付或安装前先让用户审阅并确认。
```

## 第8步：生成100个选题

用户确认Skill后，基于选题矩阵+标题公式库，生成100个选题。

### 8.1 生成规则

1. 按博主的10个栏目分配选题数量（参考博主实际分布比例）
2. 每个栏目下列出选题（纯标题，不用正文）
3. 每个栏目标注套用的博主公式
4. 末尾附**发布优先级排序**——先发哪类、再发哪类

### 8.2 交付

1. 将选题整理为 Markdown 文件并交付到当前工作区中用户可访问的位置
2. 只有用户要求且飞书集成可用时，再创建飞书文档
3. 告知用户文件位置或已创建的文档链接

## 关键约束

1. **数据驱动**：标题公式、思维模型、爆文模型必须从实际标题和正文中归纳，不编造
2. **人工筛选代表标题**：不是最高赞=最好的代表。要读标题，判断选题典型性
3. **"其他"类<10%**：超过就继续分
4. **每个模型带操作步骤**：不是空泛原则，是"你按1234做就行"
5. **防抄袭自检**：生成的内容必须和原帖拉开距离
6. **交付按当前环境适配**：默认提供 Markdown；外部文档交付须由用户提出且连接可用

## 输出检查清单

- [ ] 分析报告已交付；若创建了飞书文档，已读取核对内容
- [ ] ≥5个爆文模型，每个都有操作步骤
- [ ] "其他"类占比<10%
- [ ] 交互测试已完成（至少3个模糊想法验证）
- [ ] Skill文件已保存到正确路径
- [ ] 100个选题已交付飞书
- [ ] 生成的内容通过防抄袭自检
