# Lesson Handout Structure

Use this reference when drafting a full lesson handout, student manual section, or training-camp lesson script.

## Default Structure

Use this structure unless the user asks for a special format:

1. `本节课解决什么问题`
2. `你现在为什么会卡住`
3. `核心判断`
4. `方法/SOP`
5. `示例或演示`
6. `操作步骤`
7. `本节作业`
8. `提交物格式`
9. `自检清单`
10. `常见错误`
11. `下一步`

Keep `课程制作素材与加工说明` and `深度地图与边界` internal unless the user asks, a source gap remains, or the lesson is evidence-sensitive.

## Teachable Lesson Requirements

Every teachable lesson needs a clear learning arc and learner action. Include PPT nodes only when the user requests a deck or when the delivery format is explicitly screen-led. Name the incoming artifact from the previous lesson and the outgoing artifact used next when the lesson belongs to a sequence. A conclusion lesson should name the first post-course maintenance action.

For a substantive lesson, also show: the learner's old interpretation, the root mechanism behind it, the boundary of the method, and the signal used to judge whether the first action worked. See `teaching-depth-mechanisms.md`.

## Lesson Types

### Concept Lesson

Use when the student must change a judgment before acting.

Required sections:

- common misconception
- better frame
- concrete scene
- short practice

Avoid staying at concept level. End with a small observable action.

### Method Lesson

Use when teaching a process, rule, or repeatable method.

Required sections:

- when to use this method
- steps
- example
- checklist
- assignment

### Tool Lesson

Use when teaching Notion, AI agents, prompts, templates, or workflows.

Required sections:

- tool purpose
- input needed
- step-by-step walkthrough
- expected output
- common failure
- repair method

Do not make the tool the protagonist. The user's deliverable is the protagonist.

### Case Lesson

Use when teaching through a real or sample case.

Required sections:

- case background
- before state
- key move
- after state or output
- reusable rule
- student transfer task

### Practice Lesson

Use when the lesson is mainly an assignment.

Required sections:

- task purpose
- input materials
- steps
- time estimate
- output format
- self-check
- submission rule

### Opening Lesson / 开营课

Use when the lesson is the entry point to a course, training camp, or a new stage. It is not a shortened course introduction. Its job is to replace the learner's old explanatory frame, establish the course's first principle, make the path believable, and create the personal material that the next lesson will use.

Read `opening-lesson-design.md` first. Required sections:

- the learner's familiar scene or desired change
- why the old path repeatedly breaks (causal mechanism, not blame)
- the course's first principle and its boundary
- transformation path and the role of each stage
- learning contract: how to learn, act, reconnect after interruption, and receive feedback
- first learner asset, with a clear next-lesson handoff

Avoid: a product feature tour, generic inspiration, an overlong self-introduction, a course directory without causal explanation, or an opening task that is only a broad questionnaire.

## Length Guidance

Use flexible length based on lesson purpose:

- short practice note: 600-1000 Chinese characters
- concept lesson: 1000-1800 Chinese characters
- method lesson: 1500-2500 Chinese characters
- tool walkthrough: 1800-3000 Chinese characters
- case breakdown: 1200-2200 Chinese characters

Prefer clarity over length. A lesson is not better because it is longer.
