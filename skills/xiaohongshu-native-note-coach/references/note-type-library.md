# Note Type Library

## 1. 生活方式观点型

Use when a real life scene carries a worldview.

Structure:
```text
scene
-> what it made me realize
-> common misconception
-> deeper judgment
-> 2-3 observations
-> reminder or soft CTA
```

Best images: travel, workspace, walking, experiment, study, body/fitness, quiet reflection.

## 2. 工作流证明型

Use when screenshots or process images show how the user works.

Structure:
```text
specific workflow/result
-> old friction
-> what changed
-> 3 process points
-> why it matters
-> light product/private-chat bridge
```

Best images: Codex, Notion, automation, SOP, AI output, content pipeline.

## 3. 产品种草型

Use when introducing why a product, system, training camp, public knowledge base, or service exists.

Structure:
```text
observed problem
-> why existing approaches are not enough
-> what I built/believe
-> who it fits
-> what result/process it helps with
-> light CTA
```

Do not over-list benefits. Explain product origin and fit.

## 4. 用户案例拆解型

Use when a user/client case proves a problem or method.

Structure:
```text
case scene
-> surface problem
-> real root cause
-> advice/solution
-> general lesson
-> soft CTA
```

Anonymize details unless the user says public sharing is allowed.

## 5. 第三方故事隐喻型

Use when public events, sports, business stories, or people become a metaphor.

Structure:
```text
public story moment
-> why it hit me
-> parallel to growth/business/life
-> lesson for ordinary people
-> user's belief
```

Do not make the story about the user's own experience unless a verified parallel exists.

## 6. 发售/公开课转化型

Use for public classes, launch posts, scan-code notes, group enrollment, or campaign content.

Structure:
```text
market timing/problem
-> user's current evidence
-> what the session/product will solve
-> agenda/results
-> who should come
-> clear CTA
```

Requires exact event time, offer, CTA, and proof.

## 7. 里程碑背书型

Use when the user wants to show progress, achievement, result, collaboration, user count, publication, launch, or personal milestone.

Structure:
```text
real milestone
-> why it matters
-> where I used to be stuck
-> what I did right
-> method/system behind it
-> reminder for similar people
-> light CTA
```

Milestone expression rule: showing real progress is allowed and useful. Avoid empty showing-off by adding context, process, lesson, or reader value.

## 8. 认知判断型

Use when the note centers on a sharp judgment about AI, growth, systems, content, work, or life.

Structure:
```text
strong judgment
-> lived scene or concrete example
-> why most people misunderstand it
-> 2-4 supporting points
-> final sentence
-> comment cue
```

Need at least one concrete scene or example.

## 9. 图片海报变化/视觉迭代型

Use when a visual series shows change over time, iteration, AI generation progress, design taste, or product evolution.

Structure:
```text
what changed visually
-> what the change proves
-> bigger trend judgment
-> what becomes cheap
-> what remains valuable
-> user's principle
```

Best for AI tools, design, content production, product iteration, and taste discussion.
