# User Journey Map

Use this before designing touchpoints, onboarding, course experience, training-camp flow, service flow, AI-agent flow, or retention path.

## Principle

Do not start from "what features do I have?" Start from:

```text
第一只羊是谁？他为什么来？他想完成什么？他会怎么一步步走到结果？
```

## Required Elements

| Element | Question |
| --- | --- |
| 第一只羊 | Which representative user should the product serve first? |
| 来的原因 | What event, emotion, task, or promise brings them here? |
| 用户目标 | What result do they want, in their words? |
| 预期体验 | What do they expect to happen quickly? |
| 关键触点 | What do they see, click, read, submit, receive, or discuss? |
| 用户动作 | What must they do at each touchpoint? |
| 情绪曲线 | Where do they feel clarity, anxiety, effort, relief, delight, trust, or doubt? |
| 放弃点 | Where are they most likely to stop? |
| 峰值 | Where can they feel memorable progress, identity confirmation, or relief? |
| 终值 | How does the experience end so they want to return or recommend? |
| 回来理由 | Why would they come back next time? |

## Emotion Curve

Score each key stage from `-2` to `+2`:

- `-2`: fear, shame, confusion, heavy friction, distrust
- `-1`: effort, doubt, mild anxiety, unclear next step
- `0`: neutral, routine, no strong feeling
- `+1`: clarity, relief, progress, confidence
- `+2`: memorable high, strong identity confirmation, visible transformation

Name the lowest point, peak point, and final point.

## Evidence Rules

- User emotions should come from `user_feedback`, `client_communication`, `content`, observed behavior, or user-provided stories when possible.
- If evidence is unavailable, label the map as `假设地图` and specify the first evidence to collect.
- Do not write "用户会很爽" without naming the released tension or immediate satisfaction.
- Do not write "用户会焦虑" without naming the imagined future risk.
