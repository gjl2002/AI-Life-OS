# 朋友圈内容写回

## 授权门槛

默认只交付草稿和建议。只有用户明确要求“保存到 Notion”“加入排期”“更新这条”“写入内容库”或“标记为已发布”时，才执行写回。

“帮我写一条”“看看什么时候发”“生成文案”不构成写回授权。

## 动态目标解析

1. 调用 `$ai-life-system-init` 取得当前 Runtime。
2. 解析 `content` 概念，确认目标 `read_ready`；创建新记录时还要确认 `create_page_ready`。
3. 读取实时 schema，识别标题、正文、平台/形式、账号、类别、状态、计划时间、发布时间、来源与关系等实际字段。
4. 只填写存在且语义明确的字段；选项值必须使用 schema 中真实存在的值。
5. 如果无法判断某个字段，不要猜；将内容放入正文或先向用户确认。

## 去重

写入前查询相近时间内：

- 标题或核心判断相近；
- 正文关键句高度相似；
- 同一原始素材已产生朋友圈记录；
- 同一 Campaign 序号或作用重复。

找到明确同一记录时优先更新，不创建副本。是否覆盖正文、改变状态或调整日期必须符合用户本次授权。

## 创建与更新

创建时使用 Runtime 返回的目标数据源和父级规则，并先执行 Runtime 支持的写入检查；无法预检时至少验证目标、schema 和选项。

更新时先读取现有记录，只修改用户要求的字段或正文，保留未授权覆盖的历史信息和关系。

写入可直接发布的正文，并保留必要的内部说明，但不要把审稿分析混进公开正文。

## 回读验证

每次写入后重新读取目标记录，确认：

- 写入的是正确页面；
- 正文没有截断或重复；
- 状态、账号、类别和日期与本次授权一致；
- 未意外改动其他属性。

最终告诉用户写入了什么以及目标页面。若写入失败，保留最终草稿并说明具体阻点，不伪称成功。
